# 银行流水核对工具 v3.0

[![License: AGPL v3](https://img.shields.io/badge/License-AGPL_v3-blue.svg)](https://www.gnu.org/licenses/agpl-3.0)

这是一个面向审计和财务实务的 Windows 桌面工具。每次核对接收一份银行流水和与其对应的一份银行日记账，不合并多家银行或多个账户。它的目标不是要求做账人员把每笔流水拆得整整齐齐，而是先检查输入是否可靠，再自动找出可信的逐笔、汇总和组合关系，只把真正重要或无法可靠判断的事项留给人工在 Excel 中复核。

## 一、最重要的处理原则

主界面有三个核心参数：

| 参数 | 默认值 | 用途 |
| --- | ---: | --- |
| 实际执行重要性水平 | 100,000 元 | 控制重大匹配组和月度累计差异池是否必须人工复核 |
| 明显微小错报临界值 | 5,000 元 | 控制小额差异是否可以直接自动确认 |
| 自动确认最低综合可信度 | 70 | 控制普通候选是否可以自动确认 |

程序按以下顺序分流：

1. 匹配组金额超过“实际执行重要性水平”时，始终进入“待人工复核”。等于该水平不算超过。
2. 跨月多对多组合始终进入“待人工复核”。
3. 对方户名、对方账号等关键文字字段存在冲突，或同一记录存在多个同等候选时，始终进入“待人工复核”。金额完全一致也不能覆盖这两类风险。
4. 在未超过实际执行重要性水平且不存在上述风险的前提下，差异金额不超过“明显微小错报临界值”时，即使可信度较低也可自动确认。
5. 其余候选达到最低综合可信度时自动确认，否则进入待人工复核。
6. 没有可靠对应关系的记录归入“未找到候选”，不会伪装成已匹配。

匹配组金额采用双方绝对金额合计的较大者，不把收入和支出互相抵销。大额整组即使净差额很小，也不会因为抵销而绕过人工复核。

## 二、金额方向

程序会根据文件来源分别解释借贷方向：

| 来源 | 增加 | 减少 |
| --- | --- | --- |
| 银行流水 | 贷方、收入、收、转入等 | 借方、支出、付、转出等 |
| 企业日记账 | 借方、收入、收等 | 贷方、支出、付等 |

因此，银行流水中的“贷”表示账户资金增加，“借”表示账户资金减少；企业日记账则按银行存款科目的借增贷减处理。

无法识别的方向不会默认当作收入。程序会记录解析异常，避免静默把正负号弄反。

## 三、输入预检查

选择文件后，程序会自动分析表头位置、表头行数和派生列名。点击“开始核对”时，程序先执行输入预检查，再决定是否进入正式匹配。该功能完全固化在程序代码中，不调用也不依赖外部表头识别 Skill。

预检查包括八项：

1. **文件读取**：文件是否存在、格式是否支持、能否读取及是否有可核对数据；
2. **表格结构**：表头位置、表头层级、合并单元格、派生列名和数据区域是否可靠；
3. **日期范围**：双方最早日期、最晚日期及范围差异；
4. **金额方向**：银行流水按贷增借减，银行日记账按借增贷减；
5. **金额合计**：收入、支出分别合计和比较，不用净额抵销替代；
6. **非交易行**：合计、累计、统计、标题、重复表头、注释和空行；
7. **必填字段**：日期及当前金额模式所需的金额、借贷或方向列；
8. **辅助文字完整性**：摘要、对方户名及其他已选文字列的非空率。

检查结果分两级：

- **阻止运行**：文件无法读取、没有数据、必填列缺失、重大表头歧义、日期或金额全部失败、方向无法可靠识别。程序会说明原因并返回调整，不启动匹配；
- **提示后允许继续**：日期范围不同、收入或支出合计有差额、排除了非交易行、辅助文字不足或少量记录解析失败。程序集中展示一次，用户可继续核对或返回调整。

收入或支出差额本来就是核对对象，普通提示不会擅自把差额判断为输入错误。原始银行流水和银行日记账始终只读，不会被覆盖或回写。

## 四、程序能匹配哪些情况

程序会统一生成候选、评分，再一次性选择互不冲突的结果。主要场景包括：

- 同日同金额的一对一；
- 日期容差内的一对一；
- 白名单业务，例如手续费、利息、工资、税费；
- 原表中物理相邻、标准化摘要一致的完整连续组，对应另一侧一笔合计记录；
- 一对多和多对一组合；
- 同月 3 对 5 等多对多整组核销；
- 同日总额和同月总额核销；
- 相邻月份的一对一；
- 相邻月份的多对多候选，但这类只能待人工复核；
- 金额存在明显微小差异的候选。

连续摘要整组支持“多笔银行流水对应一笔日记账”和“多笔日记账对应一笔银行流水”。程序按原表行号判断是否真正相邻，只取完整连续组，并限制组合日期跨度；摘要为空、原表行号中断、零金额不允许或收入支出方向不能分别对应时，不会生成这类候选。

同日或同月总额核销会同时检查收入、支出的结构和金额分布，不会只看净额相等。

## 五、文字信息如何参与匹配

金额不是唯一依据。程序可以同时比较多列文字，包括：

- 摘要；
- 业务说明；
- 交易用途；
- 对方户名；
- 附言；
- 备注；
- 用户手动选择的其他文字列。

账号、卡号和凭证号不会默认勾选。凭证号主要用于报告展示，不作为默认匹配依据。

程序会记录哪些字段提供了支持、哪些字段存在冲突，并把金额分、日期分、文字分、结构分和综合可信度写入报告。

## 六、明显微小错报的月度累计

小额差异不是全年混在一起累计，而是按自然月分别累计。程序分成四个互不抵销的池：

- 银行侧独有收入；
- 银行侧独有支出；
- 日记账侧独有收入；
- 日记账侧独有支出。

每个池累计的是差异绝对额。某个月、某一池的累计值超过“实际执行重要性水平”时，该池作为一个整体进入“待人工复核”，并保留全部组成项目。其他月份和其他池不受影响。

## 七、大模型辅助

大模型是可选增强项，不是程序运行的必要条件。关闭大模型时，基础核对流程完整可用。

支持两种方式：

- 在线 API；
- 本机 LM Studio。

大模型只能在程序已经找到的候选中辅助比较文字语义，不能自行创造候选，也不能覆盖金额、重要性和跨月规则。调用失败、超时、返回格式错误或返回候选集外编号时，程序会自动退回本地评分并继续生成报告。

### 在线模式的隐私范围

在线模式只发送候选编号、日期、金额，以及摘要、业务说明、交易用途、附言、备注等允许的业务文字。账号、卡号、对方户名等敏感字段只在本机比较，在线端最多收到“相同/不同”的结论，不会收到字段原值；源文件路径和凭证号也不会发送。

### 本地模式的字段范围

本机 LM Studio 默认使用 `http://localhost:1234/v1`。除基础日期和金额外，只发送用户在“大模型辅助配置”中明确填写的本地字段。

### API 密钥

密钥只保存在当前程序会话的内存中，不写入配置文件、日志或 Excel。也可以使用环境变量：

- `BANK_RECONCILIATION_API_KEY`
- `OPENAI_API_KEY`

报告中的接口地址、错误信息和模型原始回答会先做脱敏处理。

## 八、安装和使用

### 首次安装

运行环境为 Windows 10 或 Windows 11，建议使用 Python 3.11 及以上版本。在项目目录依次运行：

```text
python -m pip install -r requirements.txt
python main.py
```

依赖清单已经包含桌面界面、Excel 读写、`.xls` 读取、数据处理和内存监控所需组件，不需要安装 Excel 插件或启用宏。以后再次使用时，只需运行 `python main.py`。

### 每次核对

1. 运行 `python main.py`，打开主窗口。
2. 选择一份银行流水和与其对应的一份银行日记账。程序会自动分析表头位置、表头行数和列名。
3. 如有需要，可调整“跳过”和“表头行数”，再使用“自动检测”。
4. 点击“配置列映射与辅助字段”，确认日期、金额方向和文字列。
5. 按项目情况调整“实际执行重要性水平”“明显微小错报临界值”和最低综合可信度。
6. 如有需要，打开“高级匹配参数”。
7. 如有需要，打开“大模型辅助（可选）—配置与测试”。
8. 点击“开始核对”。程序先执行八项输入预检查；普通提示可继续，阻止事项需返回调整。
9. 完成后，报告保存在银行流水文件所在目录，并包含“输入预检查”工作表。

报告文件名格式为：

```text
银行流水名_vs_日记账名_核对报告_时间戳.xlsx
```

支持 `.xlsx`、`.xls` 和 `.csv` 文件。

## 九、列映射模式

每份文件可独立选择：

- 借贷分列；
- 单列金额加方向；
- 单列金额含正负号。

至少要正确指定日期和金额相关列。摘要可以为空，但建议选择摘要、业务说明等文字列，以提高相同金额、多笔候选时的判断质量。

## 十、最终状态

报告只使用三个正式状态：

- 自动确认；
- 待人工复核；
- 未找到候选。

“自动确认”不等于所有项目都是精确一对一，也可能来自可靠的组合核销或明显微小差异规则。因此，报告把“精确匹配率”和“自动处理率”分开统计。

## 十一、Excel 报告

以下工作表固定生成，即使没有记录也会保留表头：

| Sheet | 作用 |
| --- | --- |
| 核对汇总 | 匹配率、自动处理率、待复核数量、阈值等总览 |
| 输入预检查 | 表头结构、日期范围、收支合计、方向、非交易行、必填字段和辅助文字完整性 |
| 每日统计 | 银行和日记账按日的收支、净额和余额对比 |
| 月度统计 | 按自然月汇总的收支、净额和余额对比 |
| 匹配明细 | 每个匹配组一行，显示最终状态、分数和理由 |
| 匹配组成明细 | 展开每个匹配组包含的原始行 |
| 明显微小错报 | 四个自然月差异池及其组成 |
| 待人工复核 | 重大组、跨月多对多和超限差异池 |
| 银行未达 | 银行侧未找到候选的原始记录 |
| 日记账未达 | 日记账侧未找到候选的原始记录 |
| 运行参数 | 本次核对实际使用的参数和随机种子 |

按数据情况还可能生成：

- 余额差异明细；
- 余额连续性异常；
- 大模型辅助明细；
- 解析异常明细。

### 如何人工复核

复杂信息不在小窗口里处理，而是在 Excel 的“待人工复核”Sheet 中处理：

- “复核结论”下拉选项为“接受、拒绝、暂不处理”；
- 默认值为“暂不处理”；
- “复核说明”用于填写判断依据；
- 需要逐笔查看时，通过“复核事项ID”或“匹配ID”到“匹配组成明细”查找原始组成。

## 十二、高级参数

大多数项目保持默认值即可。常用参数包括：

- 日期容差：普通一对一允许跨日或跨月的天数；
- 组合窗口：组合候选可跨越的最大日期范围；
- 组合最大深度：单个组合允许包含的最大笔数；
- 批量最少笔数：工资、代发等批量场景的起始门槛；
- 每笔最大候选数：限制候选爆炸；
- 内存限制：内存偏高时自动降级为更保守的处理方式；
- 随机种子：`0` 等固定值便于复现；`-1` 表示每次使用新的实际种子，报告会同时记录请求值和实际值。

停止按钮会通知匹配器尽快结束。已生成的原始文件不会被改动。

```text
application.py       无界面的完整核对流程
data_loader.py       文件读取、金额方向和数据清洗
input_precheck.py    自包含表格结构识别与八项输入预检查
matching_policy.py   评分、重要性分流和月度差异池
matcher.py           候选生成、组合匹配和统一选择
llm_assistant.py     在线 API 与 LM Studio 可选辅助
reporter.py          Excel 报告数据和复核表
make_excel.py        Excel 样式输出
gui.py               Windows 桌面界面
main.py              程序入口
requirements.txt     Python 运行依赖清单
tests/               自动测试
```
