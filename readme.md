# 银行流水核对工具 v3.1

[![License: AGPL v3](https://img.shields.io/badge/License-AGPL_v3-blue.svg)](https://www.gnu.org/licenses/agpl-3.0)

这是一个面向审计项目的 Windows 桌面工具。每次核对接收一个银行账户的流水及其对应的银行存款序时账（旧界面和报告中也称“日记账”）。当前集中处理单账户的合并拆分、工资等批量收付款，不做多文件合并、多账户批量或企业财务月度对账。程序自动生成对应关系、组级结论和疑点明细，不要求先填写人工结论才能出报告。

## 一、最重要的处理原则

主界面有三个核心参数：

| 参数 | 默认值 | 用途 |
| --- | ---: | --- |
| 实际执行重要性水平 | 100,000 元 | 控制单项及月度累计事项的高风险分级和展示优先级 |
| 明显微小错报临界值 | 5,000 元 | 控制可量化小额差异是否自动归集为低风险事项 |
| 自动确认最低综合可信度 | 70 | 在候选关系已经成立的前提下，控制普通候选的自动确认 |

程序按以下顺序分流：

1. 金额、方向和必要文字证据成立且关系唯一时，自动确认一对一、一对多、多对一或多对多关系。
2. 存在多个合理拆分，但同一账户、币种、期间内的整个交易组收入和支出分别闭合时，输出“整组勾稽一致”，不虚构逐笔对应。
3. 非零差异、跨期、关键字段冲突或候选歧义先计算影响金额，再按两个重要性阈值自动分级；这些事项仍会完成处理和输出。
4. 影响不超过明显微小错报临界值时，自动归集为低风险；超过该临界值但不超过实际执行重要性水平时为中风险；超过实际执行重要性水平时为高风险。
5. 明确定性高风险直接列为高风险；影响无法量化或核对范围身份冲突时列为“范围未知”。
6. 没有足够证据建立关系的记录分别进入“银行侧待查”或“日记账侧待查”，不会伪装成已匹配。
7. 所有状态都是程序的完整结果，不存在必须等待用户处理才能结束的状态。

匹配组金额采用双方绝对金额合计的较大者，不把收入和支出互相抵销。重要性水平只负责风险分级，不会单独证明两条记录属于同一业务。

## 二、金额方向

程序会根据文件来源分别解释借贷方向：

| 来源 | 增加 | 减少 |
| --- | --- | --- |
| 银行流水 | 贷方、收入、收、转入等 | 借方、支出、付、转出等 |
| 企业日记账 | 借方、收入、收等 | 贷方、支出、付等 |

因此，银行流水中的“贷”表示账户资金增加，“借”表示账户资金减少；企业日记账则按银行存款科目的借增贷减处理。

无法识别的方向不会默认当作收入。程序会记录解析异常，避免静默把正负号弄反。

## 三、输入检查

选择文件后，程序会自动分析表头位置、表头行数和派生列名。点击“开始核对”时，程序先执行输入检查，再进入正式匹配。该功能完全固化在程序代码中，不调用也不依赖外部表头识别 Skill。

输入检查包括十一项：

1. **文件读取**：文件是否存在、格式是否支持、能否读取及是否有可核对数据；
2. **表格结构**：表头位置、表头层级、合并单元格、派生列名和数据区域是否可靠；
3. **日期范围**：双方最早日期、最晚日期及范围差异；
4. **核对账户**：识别本方账号缺失、混合或双方冲突；
5. **核对币种**：识别币种缺失、混合或双方冲突；
6. **金额方向**：银行流水按贷增借减，银行日记账按借增贷减；
7. **金额合计**：收入、支出分别合计和比较，不用净额抵销替代；
8. **非交易行**：合计、累计、统计、标题、重复表头、注释和空行；
9. **数据人口**：解释原始行、有效交易、非交易行和解析异常的去向；
10. **必填字段**：日期及当前金额模式所需的金额、借贷或方向列；
11. **辅助文字完整性**：摘要、对方户名及其他已选文字列的非空率。

检查结果分三级：

- **通过**：当前项目未发现影响使用的异常；
- **疑点**：日期范围不同、账户币种缺失或冲突、收支合计有差额、存在非交易行、辅助文字不足或局部解析失败。程序记录疑点并自动继续；
- **无法计算**：文件没有数据、必填映射无效，或任一侧没有任何有效日期、金额或交易。只有客观上无法计算时才停止并说明原因。

收入或支出差额本来就是核对对象，业务疑点不会弹出确认窗口，也不会擅自被判断为输入错误。原始银行流水和银行日记账始终只读，不会被覆盖或回写。

## 四、程序能匹配哪些情况

程序会统一生成候选、评分，再一次性选择互不冲突的结果。主要场景包括：

- 同日同金额的一对一；
- 日期容差内的一对一；
- 白名单业务，例如手续费、利息、工资、税费；
- 原表中物理相邻、标准化摘要一致的完整连续组，对应另一侧一笔合计记录；
- 一对多和多对一组合；
- 依据业务编号或批次形成的非相邻完整组，双向支持；
- 不等额工资明细对应汇总账，夹入的无关付款仍单独保留；
- 同业务的多对多，例如银行150+450对应序时账100+200+300；
- 同月 3 对 5 等多对多整组核销；
- 同日总额和同月总额核销；
- 相邻月份的一对一；
- 相邻月份的多对多候选，由程序按影响金额和定性证据自动分级；
- 金额存在明显微小差异的候选。

连续摘要整组支持“多笔银行流水对应一笔日记账”和“多笔日记账对应一笔银行流水”。程序按原表行号判断是否真正相邻，只取完整连续组，并限制组合日期跨度；摘要为空、原表行号中断、零金额不允许或收入支出方向不能分别对应时，不会生成这类候选。

同日或同月总额核销会同时检查收入、支出的结构和金额分布，不会只看净额相等。明确不同业务、批次或对方的记录，不能因为总额相等就合并；有更充分业务依据的真实差额，也不能被弱依据的同额记录挤掉。同额确有多种合理去向时，报告保留竞争组成。

有明确范围的工资完整组不受通用30笔组合候选上限影响。缺少分组依据时，通用组合仍有候选数量和深度边界，程序不承诺穷尽任意规模的所有组合；本次实际搜索覆盖情况记录在运行参数中。

## 五、文字信息如何参与匹配

金额不是唯一依据。程序可以同时比较多列文字，包括：

- 摘要；
- 业务说明；
- 交易用途；
- 对方户名；
- 附言；
- 备注；
- 业务号、业务编号、批次号、批次编号、订单号、合同号、结算号；
- 交易流水号、回单号等辅助原始文字；
- 用户手动选择的其他文字列。

账号、卡号和凭证号不会默认作为辅助文字勾选。凭证号可用于序时账侧的分组边界与原行展示，相同凭证号跨年度或期间不能合并成一个凭证组。每笔银行流水号不等于工资批次号；编号缺失也不是无法核对，程序继续使用可用的日期、用途和对方信息。

程序会记录哪些字段提供了支持、哪些字段存在冲突，并把金额分、日期分、文字分、结构分和综合可信度写入报告。

## 六、明显微小错报的月度累计

小额差异不是全年混在一起累计，而是按自然月分别累计。程序分成四个互不抵销的池：

- 银行侧独有收入；
- 银行侧独有支出；
- 日记账侧独有收入；
- 日记账侧独有支出。

每个池累计的是差异绝对额。某个月、某一池的累计值超过“实际执行重要性水平”时，该池及其组成项目自动升级为高风险疑点，程序仍正常完成并保留全部组成。其他月份和其他池不受影响。

## 七、大模型辅助

大模型是可选增强项，不是程序运行的必要条件。关闭大模型时，基础核对流程完整可用。

支持两种方式：

- 在线 API；
- 本机 LM Studio。

大模型只能在程序已经找到的候选中辅助比较文字语义，不能自行创造候选，也不能覆盖金额、重要性和跨月规则。调用失败、超时、返回格式错误或返回候选集外编号时，程序会自动退回本地评分并继续生成报告。

### 在线模式的隐私范围

在线模式只发送候选编号、日期、金额，以及摘要、业务说明、交易用途、附言、备注等允许的业务文字。账号、卡号、对方户名等敏感字段只在本机比较，在线端最多收到“相同/不同”的结论，不会收到字段原值；源文件路径和凭证号也不会发送。

### 本地模式的字段范围

本机 LM Studio 默认使用 `http://localhost:1234/v1`。除基础日期和金额外，只发送用户在“大模型辅助配置”中明确填写的本地字段。

### API 密钥

密钥只保存在当前程序会话的内存中，不写入配置文件、日志或 Excel。也可以使用环境变量：

- `BANK_RECONCILIATION_API_KEY`
- `OPENAI_API_KEY`

报告中的接口地址、错误信息和模型原始回答会先做脱敏处理。

## 八、安装和使用

### 首次安装

运行环境为 Windows 10 或 Windows 11，建议使用 Python 3.11 及以上版本。在项目目录依次运行：

```text
python -m pip install -r requirements.txt
python main.py
```

依赖清单已经包含桌面界面、Excel 读写、`.xls` 读取、数据处理和内存监控所需组件，不需要安装 Excel 插件或启用宏。以后再次使用时，只需运行 `python main.py`。

### 每次核对

1. 运行 `python main.py`，打开主窗口。
2. 选择一份银行流水和与其对应的一份银行日记账。程序会自动分析表头位置、表头行数和列名。
3. 如有需要，可调整“跳过”和“表头行数”，再使用“自动检测”。
4. 点击“配置列映射与辅助字段”，确认日期、金额方向和文字列。
5. 按项目情况调整“实际执行重要性水平”“明显微小错报临界值”和最低综合可信度。
6. 如有需要，打开“高级匹配参数”。
7. 如有需要，打开“大模型辅助（可选）—配置与测试”。
8. 点击“开始核对”。程序先执行十一项输入检查；业务疑点自动记录并继续，只有没有计算条件时才停止。
9. 完成后，报告保存在银行流水文件所在目录，并包含“输入检查”工作表。

报告文件名格式为：

```text
银行流水名_vs_日记账名_核对报告_时间戳.xlsx
```

支持 `.xlsx`、`.xls` 和 `.csv` 文件。

## 九、列映射模式

每份文件可独立选择：

- 借贷分列；
- 单列金额加方向；
- 单列金额含正负号。

至少要正确指定日期和金额相关列。摘要可以为空，但建议选择摘要、业务说明等文字列，以提高相同金额、多笔候选时的判断质量。

## 十、最终状态

报告使用五个正式状态：

- 自动确认；
- 整组勾稽一致；
- 自动归集事项；
- 疑点事项；
- 未找到候选。

状态描述程序已经完成了什么，风险等级另行使用“正常、低风险、中风险、高风险、范围未知”。“整组勾稽一致”只确认交易组整体闭合，不声称已经找到唯一逐笔关系。因此，报告把“逐笔精确匹配率”“组级勾稽率”和“自动完成率”分开统计。

## 十一、Excel 报告

正常流程按以下顺序生成业务成果：

| Sheet | 作用 |
| --- | --- |
| 核对结论 | 范围状态、自动完成率、各状态数量和金额、风险金额、两侧待查、余额状态、处理进度及三项建议动作 |
| 疑点事项 | 程序已经判定的疑点、风险、依据、建议动作和双方核心证据 |
| 自动归集事项 | 明显微小差异及其自然月累计池 |
| 银行侧待查 | 银行侧尚未形成可靠关系的原始记录 |
| 日记账侧待查 | 日记账侧尚未形成可靠关系的原始记录 |
| 逐笔匹配 | 一对一关系及系统结论，按状态区分已确认、差额和疑点 |
| 整组勾稽 | 一对多、多对一、多对多及日月总额等组级结论 |
| 匹配组成 | 每个匹配组的全部原始组成；交易金额按正数展示，收支方向单列 |
| 其他可能对应明细 | 有竞争关系时生成，按匹配ID和对应方案逐行列出完整原始组成，不把竞争方案当作已确认关系 |
| 输入检查 | 文件、结构、期间、账户、币种、收支、人口和字段完整性 |
| 月度统计 | 按自然月汇总的收支、净额和余额对比 |
| 每日统计 | 按日汇总的收支、净额和余额对比 |
| 运行参数 | 本次实际参数和随机种子，默认隐藏 |

按数据情况还可能生成：

- 余额差异明细；
- 余额连续性异常；
- 大模型辅助明细；
- 解析异常明细。

“运行参数”“大模型辅助明细”“解析异常明细”等技术工作表默认隐藏。候选ID、阶段、评分拆分、差异池ID和模型记录等机器字段保留在报告中，但默认隐藏；需要追溯时可以在 Excel 中取消隐藏。

匹配表公开“业务分组依据”和“其他可能对应”。核对结论分别列出银行、序时账的已核对笔数覆盖率及金额覆盖率：只计算零差额的自动确认和整组勾稽一致，金额使用绝对值相加，不用收支净额。自动完成率包含疑点分析，不表示全部交易已经匹配；旧结果缺少核对状态依据时，覆盖率明确标为无法计算。

### 可选后续标注

“疑点事项”提供“后续状态、处理说明、调整凭证号、责任人、处理日期”五列，全部默认为空，不填写也不影响程序结论或完成状态。

“后续状态”可选“已关注、已处理、无需处理”。用户主动选择后，“核对结论”中的“待处理事项数、已关注事项数、已处理事项数、无需处理事项数”会通过普通 Excel 公式自动更新，不需要宏、插件或把文件重新导回程序。

需要查看组成时，可通过“匹配ID”在“匹配组成”中定位原始记录。金额列表示交易规模并统一为正数，“收支方向”表示收入或支出；只有净额列保留正负号。

## 十二、高级参数

大多数项目保持默认值即可。常用参数包括：

- 日期容差：普通一对一允许跨日或跨月的天数；
- 组合窗口：组合候选可跨越的最大日期范围；
- 组合最大深度：单个组合允许包含的最大笔数；
- 批量最少笔数：工资、代发等批量场景的起始门槛；
- 每笔最大候选数：限制候选爆炸；
- 内存限制：内存偏高时自动降级为更保守的处理方式；
- 随机种子：`0` 等固定值便于复现；`-1` 表示每次使用新的实际种子，报告会同时记录请求值和实际值。

停止按钮会通知匹配器尽快结束。已生成的原始文件不会被改动。
