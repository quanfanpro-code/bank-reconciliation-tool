# 银行流水核对工具 v3.2

按同一账户的银行流水和银行日记账双向核对。输出一份 Excel，保留双方原始记录及对应关系。

## 安装和运行

需要 Windows、Python 3.11 或更新版本和本机 Microsoft Excel。双击 `启动银行流水核对工具.cmd`，或在项目目录运行：

```powershell
python -m pip install -r requirements.txt
python main.py
```

需要独立 Windows 程序时运行 `打包银行流水核对工具.cmd`，使用 `dist/银行流水核对工具.exe`。正常情况下由本机 Excel 打开并验证报告。Windows 拒绝启动 Excel 时，程序检查五张表、人工填写区和明细跳转，Excel 在用户打开时计算跳转公式。

## 每次核对

1. 分别选择同一账户的银行流水和日记账。程序读取表头和行数据，先确认交易日期、金额、方向、余额、本方账号和币种，再逐笔匹配。支持收付分列、单列带正负号、金额与方向分列。日记账分列的收入按借方读入，支出按贷方读入。调整表格列顺序不会改变识别结果。起息日期、手续费金额、可用余额和付款人或收款人账号各有自己的业务含义。遇到两个列名都说得通时，先尝试用原表的余额变动验证，仍无法区分时打开“配置列映射与辅助字段”确认。旧模板的交易列会根据当前文件重新识别。
2. 按本次项目设置明显微小错报临界值、实际执行重要性水平及允许的日期间隔。点击“开始核对”。
3. 打开报告看各月、各日的收支和余额。需要人工查看的记录在“待核对”填写核查结论和备注。填写不会修改原始金额或程序对应关系。

## 核对顺序

- 先确认有明确依据的逐笔交易。已对上的记录退出后续搜索。
- 再处理剩余交易的跨日、合并记账、退回和重付。前后余额一致、剩余收支组合唯一且用途无冲突时，可自动确认合并关系。普通账户列核实为同一账户即可使用余额证据，核对总览显示是否启用。原始交易日期不变。
- 最后按本次设置分配人工核对。明显微小错报临界值以内的差额留在明细；介于两项阈值之间的进入抽查范围；超过实际执行重要性水平的逐项核对。同月、同来源、同方向的未解释差额按原月累计。两个阈值不参与寻找交易对应关系。

## 五张工作表

| 工作表 | 内容 |
| --- | --- |
| 核对总览 | 输入文件、账户、期间、读入笔数、月度核对结果及人工核对事项数 |
| 月度核对 | 比较银行和账上每月的收入、支出、月末余额和笔数差额 |
| 日度核对 | 按原日期比较收款、付款和日末余额，标明已对上但日期不同的记录 |
| 待核对 | 要逐项核对或抽查的事项，说明具体冲突和为何需要核查，可跳到交易明细。核查结论和备注可以自由填写 |
| 交易明细 | 每笔原始记录只列一次，同一编号用于标记对应关系。保留日期、收支金额、余额、对方、备注、凭证号和原表位置 |

## 可选大模型辅助

桌面版可配置在线服务或本机兼容服务。模型只辅助比较未确认的文字证据，原始交易和金额由程序核验。服务失败时继续使用本地匹配。在线模式限既有允许字段，账号等敏感信息留在本机。个人配置文件和密钥不随源码发布。

报告保存在银行流水文件所在目录，也可以用“打开最近报告”重开已保存的报告。重新核对生成新文件。

## 在 Codex 中通过问答核对

在项目中调用 `$bank-reconciliation-agent`。Agent 通过提问确认要核对的两个文件或两个目录、重要性金额和报告保存位置。桌面程序和 Skill 使用同一套字段识别和核对代码，每户输出同样的五张表。某个账户的原表字段有歧义时，Skill 在问题卡列出具体文件和候选列，确认后只补跑该户。其他账户照常核对。交易用途由当前 Agent 判断，直接使用本次会话的模型。有可区分的原表依据且通过收支金额、方向和冲突核验后，Agent 可确认对应关系。低于确认门槛或未通过检查的答复只留复核记录，不改变原候选；留存、抽查和逐项核查仍由重要性水平决定。每次复核单独计时，报告和任务结果显示已完成、超时、未复核的次数。
