## 二、已落实的核心业务规则

1. 主界面使用三个完整名称：
   - 实际执行重要性水平，默认 100,000 元；
   - 明显微小错报临界值，默认 5,000 元；
   - 自动确认最低综合可信度，默认 70。
2. 匹配组金额取银行侧和日记账侧绝对金额合计的较大者，收入与支出不抵销。
3. 组金额超过实际执行重要性水平时必须待人工复核；等于该水平不算超过。
4. 未超过实际执行重要性水平，且差异不超过明显微小错报临界值时，可不受最低可信度限制自动确认。
5. 明显微小错报按自然月、来源和收支方向拆成四个池，分别累计绝对差异。
6. 单个月份、单个差异池累计超过实际执行重要性水平时，整池作为一项待复核事项，并保留全部组成。
7. 同月多对多可以自动组合；跨月多对多始终待人工复核；普通一对一可在日期容差内跨月。
8. 最终状态统一为“自动确认、待人工复核、未找到候选”。
9. 精确匹配率与自动处理率分别披露。
10. 人工复核在 Excel 中完成，复核结论为“接受、拒绝、暂不处理”，默认“暂不处理”。

## 三、主要致命问题和质量问题修复

### 金额与业务口径

- 修正银行流水“贷为增加、借为减少”的方向，企业日记账仍按银行存款科目“借增贷减”处理。
- 单列金额加方向现在同时参与期初余额推算，不能识别的方向会记录异常，不再静默猜测。
- 修正日总额、月总额和批量工资边界，避免把普通重复流水误当批量业务。
- 支持 3 对 5 等同日、同月多对多整组核销。
- 支持一对多、多对一存在明显微小差异时形成近似组合。
- 组合阶段不再把一对一精确项重复包装成组合，减少虚假歧义和无效大模型调用。
- 候选统一评分后再一次性选择，避免同一笔记录被多个结果重复占用。

### 重要性与累计

- 所有匹配路径统一计算组金额、收入差异、支出差异、总差异和 0～100 综合可信度。
- 重大事项、跨月多对多、明显微小错报和普通低可信度事项按严格优先顺序分流。
- 月度差异池超限后，池内原自动确认项目会同步改为待人工复核，报告口径不再前后矛盾。

### 文字与大模型

- 可同时使用摘要、业务说明、交易用途、对方户名、附言、备注等多列文字。
- 账号、卡号和凭证号不默认勾选；凭证号只用于展示。
- 本地规则会记录字段支持证据和敏感账户字段冲突。
- 在线大模型只接收允许的业务文字；账号、卡号、对方户名等只在本机比较，在线端最多接收“相同/不同”结论，不接收原值。
- 本地 LM Studio 只接收用户明确填写的文字字段；空选择不会偷偷退回默认字段。
- 大模型只能从已有候选中辅助文字语义，不能创造候选或覆盖金额、重要性、跨月和累计规则。
- 超时、断网、协议不兼容、格式错误或候选编号越界时，自动退回本地评分并继续出报告。
- API 密钥只存在当前会话内存，可从环境变量读取；日志、报告、错误和模型原始回答均做脱敏。

### Excel 报告与 Windows 稳定性

- 报告增加组级、组成级、明显微小错报、待人工复核和大模型辅助的详细证据。
- 待人工复核表直接列出原文件行号、日期、逐笔金额、摘要、辅助文字、四项评分、阈值依据、差异池和候选编号。
- 所有数据页已增加表头筛选并冻结首行，复杂事项可以直接在 Excel 中筛选和填写。
- 用户文字做了 Excel 公式注入防护。
- 小批量任务不再强行启动后台多进程。
- 后台进程无法启动或异常退出时，会退回单线程继续处理，不再让整次核对作废。
- Windows 中文控制台无法显示日志图标时会自动替换图标，不再因日志编码错误中断核对。
