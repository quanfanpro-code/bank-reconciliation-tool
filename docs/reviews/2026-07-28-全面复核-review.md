## 三、阶段 5 新发现问题与处置（端到端冒烟驱动）

审查不是走过场——冒烟首轮即暴露 1 个 P1 业务 bug 与若干问题，全部按 TDD（先红后绿）修复：

| 级别 | 问题 | 根因 | 处置 |
|------|------|------|------|
| 🔴 P1 | 用「收/付」标注方向的流水，支出整行被静默丢弃 | `DIRECTION_MAP` 有「收」无「付」，非法方向按解析异常丢行 | 词表补「付/付款/收款」；冒烟证明修复前银行 4 行只剩 2 行、修复后全保留且无解析异常 |
| 🟡 P2 | 未达 sheet 金额/余额为字符串，Excel 无法求和 | `get_unmatched` 对 object 列一律 `clean_excel_string`（load_file 按 dtype=object 读取） | 新增 `_restore_numeric_cells`，金额/余额类列还原为数值 |
| 🟡 P2 | 余额连续性检查遇空余额日断链，其后首日错误无法检出 | `shift(1)` 取上一日余额遇空即跳过 | 重写为「基准余额+区间净额」跨空日累计校验；冒烟故意做错的 106900 被正确检出（差 50） |
| 🟡 P2 | 汇总表期初余额为字符串 "100,000.00" | 期初区块用 f-string 千分位格式化 | 改 float 值，千分位交由单元格格式 |
| 🟡 P2 | 「期间净额」列负净额在 Excel 显示为 1899-08-02 | 列名「期间」命中 make_excel 日期关键词，-150 被套日期格式 | 列名改「区间净额」；make_excel money 关键词同步补「余额」（两处推断函数） |
| 🟢 P2 | `DataLoader.chunksize` / `load_file(chunksize)` 死参数 | Excel 不支持分块，参数从未生效 | 参数删除，GUI 调用同步清理 |

每项修复均有对应回归测试：收付标注、数值还原、跨空余额日、期初数值、区间净额非日期、余额列推断。

## 四、Code Review 观察项（非阻塞，如实记录）

- 🟢 `MatcherConfig.allow_mixed_sign` dataclass 默认仍为 `True`：GUI 层默认已对齐 readme（False），
  API 直用 `MatcherConfig()` 时为 True。验收标准只约束 GUI 层，未动；后续如需严格一致可再收。
- 🟢 空 DataFrame 的 sheet 被 `make_excel` 跳过（0 未达账项时对应 sheet 不出现）：
  既有行为，readme 总览表已如实注明「无对应数据的 Sheet 会自动省略」。
- 🟢 汇总表「匹配率」为格式化字符串（如 `100.0%`）：展示型字段，合理保留。
- 🟢 并行匹配在脚本缺少 `if __name__ == '__main__'` 保护时会 BrokenProcessPool 并走兜底——
  本轮 P2 修复的异常记录链路将其如实记入「运行异常统计」，行为符合设计；GUI 入口有
  `freeze_support()`，不受影响。

## 五、Ponytail 结论
