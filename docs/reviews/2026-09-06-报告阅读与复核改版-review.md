## 二、交付行为

1. 只默认显示核对概览、待复核事项、全部核对明细。旧证据表以及新增来源、事项索引保留在隐藏附表中。
2. 首页说明账户、期间、双方笔数、结果、待复核事项、跨期和资料限制。跨期小额即使自动确认，也能从首页找到期间核查事项。
3. 同一明确对应关系的金额差异和跨期问题集中列示，问题栏直接写出问题，双方日期、摘要、对方、业务编号和金额在旁边展示。
4. 逐笔并排展示；整组先看业务合计，下方可展开双方全部组成，组内不确定关系不虚构逐条配对。点击待复核事项编号直接进入完整明细。
5. 低风险及未抽中中风险继续留存备查；现有风险和抽样信息保留在技术附表。人工状态可留空，选择后可通过普通 Excel 公式查看已处理数量。
6. 新格式筛选导出保持三张主表，重算选中记录数和事项数，说明来源报告、筛选条件及实际金额覆盖比例。全局资料和余额限制保留并交代全量口径；旧格式继续兼容。

## 三、审查发现与修复

| 发现 | 修复及验证 |
| --- | --- |
| 原报告表格多、首页未突出小额跨期关系 | 统一三张主表；跨年 3,000 元场景验证首页和待复核清单均提示期间核查 |
| 仅将技术字段隐藏仍不能说明完整业务 | 为双方明细补充对方、业务编号与原行；整组两笔对三笔完整带出五条组成 |
| 同一业务可能同时出现在金额和跨期专题 | 按明确的原匹配关系归并为一个事项；30,000 元差异且跨期的场景仅列一项 |
| 阅读来源记录重复用于构造时，旧事项编号会使单边记录被跳过 | 每次构造重新分配阅读编号；重复构造仍保留全部单边记录 |
| 筛选输出不同名称可能实际指向原文件 | 增加同一实际文件识别；硬链接测试验证拒绝覆盖且源文件校验值不变 |
| Excel 概览初次渲染分成两页，问题文字仍偏长 | 调整一页概览、表头对齐和行高；问题栏压缩为金额、期间或对应问题，详细依据放在完整明细 |
| 主表沿用“自动归集事项”使结果不够明确 | 主表改为“金额差异，需核查”等业务结论，技术附表仍保留原处理状态 |
| 筛选目标覆盖比例不等于整组带出后的实际比例 | 首页同时说明实际选中金额、全量业务金额和实际比例；目标 50%、实际带出 80% 的场景验证通过 |
| 原测试要求旧核对结论可见，与新需求冲突 | 仅调整该可见性断言，保留旧证据验证，并增加新首页可见及搜索限制仍披露的检查 |

所有新增功能与上述边界修复均先观察到针对性测试失败，再实现并验证。初次测试自身的工作簿关闭写法曾有错误，修正后重新确认真实行为失败，未将测试代码错误当作有效失败证据。
