# 银行流水核对 Skill 方案

## 已确认的需求

一次可核对一个账户，也可接收两个目录批量核对。每户只使用银行流水和银行日记账。输出沿用修复后的五张表，分别为核对总览、月度核对、日度核对、待核对和交易明细。沿用本次设置的明显微小错报临界值和实际执行重要性水平。运行 Skill 的 Agent 负责读懂文字，不另外配置模型服务或 API 密钥。

用户操作统一通过 Agent 提问完成。优先用提问界面，问题允许用户选项或填写路径。使用上下文已给出的信息，只问本次仍缺的输入、参数或需要用户作决定的文件冲突。匹配判断由程序和 Agent 自己处理；程序内部的执行参数由 Agent 根据用户答案填写。工具完成后直接交付结果。

## 方案对比

| 方案 | 怎样运行 | 影响 |
| --- | --- | --- |
| 复用修复后的核对程序 | 增加文件对和目录入口。在程序确认了明确对应后，把剩余的合理候选交给当前 Agent 判断文字证据，再由同一程序生成五表 | 两个入口共用金额、日期、余额、人工分流和报告逻辑。用少量代码完成本地交接 |
| Skill 单独实现核对 | Agent 使用独立脚本完成读取、配对和报告 | 实现和验证重复，已有修复需要维护两份，两个入口可能得出不同结果 |
| 桌面程序先出报告，Agent 只加说明 | Skill 读取已生成的报告，解释待办 | Agent 无法改善实际配对，人工待办数量也不会因有效语义判断而减少 |

用户选定第一种。沿用桌面程序已经通过真实资料核对的匹配顺序。

## 输入、判断和交付

单户入口读取两个文件。目录入口按公司、银行和完整账号成对执行，保留账号前导零，排除已生成的报告和模板。对重复或缺配的账户列清文件，其余账户继续。逐户报告单独保存，源文件保持原样。

程序先确认明确交易，再处理余额能勾稽的同段记录。若剩余记录仍有合理的对应分歧，向当前 Agent 提供相关日期、金额、用途及必要的文字证据。Agent 返回候选编号和判断依据，也可以保留疑点。程序检查编号属于当前任务、收支方向及金额成立、原始行未被其他关系占用。模型意见不能改变原始数据或跳过硬性校验。未收到有效意见时按现有程序继续并如实保留疑点。

报告使用同一生成和验证流程。两种入口使用相同的输入和配置时，金额、原始行归属和输出格式应一致。测试从单户、目录配对、合记、有效意见、无效意见和部分失败覆盖，不需要额外模型服务。
