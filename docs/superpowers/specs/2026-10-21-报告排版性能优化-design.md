# 报告排版性能优化 — 方案设计

日期：2026-10-21
状态：阶段 2 方案设计（待用户批准）
需求文档：`docs/requirements/2026-10-21-报告排版性能优化-requirement.md`

## 排版链路现状（代码已逐行读过）

`_generate_report`（`reporter.py:2419`）目前的流程：

1. `build_report_tables` 构造 34 张 DataFrame（纯内存，41 秒）。
2. `make_excel` 普通模式写数据＋摩根系主题样式，保存（125 秒）。
3. **排版环节**重新 `load_workbook` 读回，依次执行：
   - `reporter._postprocess_summary / _postprocess_details / _postprocess_diff_columns`：风险着色、差额着色；其中 `_postprocess_details` 对大表执行 `delete_cols`（逐格搬迁，超线性，是大表重灾区）。
   - `reporter._apply_report_presentation`：对全部 34 张表逐列逐格设对齐、数字格式，并逐字算中文宽度定行高。
   - `复核报表.apply_review_presentation`：往 7 张表逐行写人工核对公式；`_format_sheets` 逐格刷主表样式。
   - `报告展示.format_display_sheets`：写阅读表公式，逐格刷样式、设置 outline 折叠、追加年度合计行。
   - `紧凑报告.apply_compact_report`：新建待处理事项、对应明细、核对总览三张表（读已写入的表再加工）；随后 `format_compact_sheet` 对全部 34 张表**再逐格刷一遍**最终样式。
4. 整体 `save` 保存（读回后的保存实测异常缓慢，见下）。

关键观察：**后面的层会覆盖前面层的样式**（主题样式 → 复核绿表 → 展示蓝表 → 紧凑报告终样）。最终视觉效果主要由最后一层决定，早期层的大半逐格工作是被覆盖的浪费。

## 已核实的关键数字

| 事实 | 数字 | 来源 |
|---|---|---|
| 初次写入 30 万行（普通模式，含保存） | 124.8 秒 | 运行日志 2026-10-21 |
| load_workbook 读回（空载复测） | 120.0 秒 | 实测 |
| 读回后再 save（空载复测） | 71.6 秒 | 实测（此前 48 分钟系两个排版进程抢占 CPU 所致的误测） |
| 完整 5 遍排版 | 7 小时以上未完成 | 运行日志 |

空载复测结论：读回+重存地板约 3.2 分钟，加上至少一遍逐格操作后总量仍超 5 分钟目标，"读回—修改—重存"路线依然不达标，方案方向不变。附带好消息：普通模式保存只要约 72 秒，新写入器**不需要** write-only 模式，避开其行高/列宽须先于写入等限制，实现风险更低。

## 候选方案

### 方案甲（推荐）：排版前置 + 单次写入成型

新增"排版计划"层：在 DataFrame 阶段就把每张表的最终形态算完——最终列集合（预先删掉 `_低置信度标记` 等列，不再 `delete_cols`）、行顺序（核对结论排序、年度合计行）、每个单元格的最终样式（按"最后一层说了算"直接算终态，不做被覆盖的中间样式）、行高/隐藏/outline、列宽/隐藏、冻结、筛选、数据验证、条件格式、批注、超链接、公式单元格、打印设置、表顺序与隐藏状态。然后一个写入器一次性把数据＋公式＋样式写出，只保存一次。

- 实现成本：高。要把 5 个文件约 1,500 行排版逻辑逐条翻译成"从 DataFrame 计算"，是机械但量大的工作。
- 维护成本：低。排版规则集中在一处，不再分散五处互相覆盖。
- 风险：中。翻译遗漏会改变效果——靠逐格对比金样兜底。
- 兼容性：高。报告结构、列名、公式语义不变，筛选视图不受影响。
- 可逆性：高。旧排版函数保留一个版本周期，内部开关切回，兼作对比基准。
- 预期：构造 41 秒 + 计划计算（纯内存）+ 单次写入保存约 2~3 分钟 → 合计 ≤ 5 分钟，达标。

### 方案乙：保留读回排版，逐点消除热点

`delete_cols` 改为写入前删列；5 遍合 1 遍；宽度/行高计算向量化。

- 实现成本：中。但改动同样遍布 5 个文件。
- 致命伤：绕不开"读回＋重存"。空载实测读回 120 秒＋重存 72 秒＝3.2 分钟地板，再加一遍逐格操作，总量稳超 5 分钟目标。
- 结论：不达标，排除。

### 方案丙：大小账户双轨

小账户走原路径，大账户出毛坯报告、排版另做。

- 违反"效果一丝不能差"和单一交付物原则；增加长期分支复杂度。
- 结论：排除。

## 推荐方案的数据流

```
matcher 结果
  → build_report_tables（现有，不动）→ dict[str, DataFrame]
  → build_review_tables / apply_column_preferences（现有，不动）
  → 【新】排版计划计算：tables + 事项结构 → list[SheetPlan]
        SheetPlan = 最终行列内容（含公式、年合计行）+ 每格样式终态
                  + 行/列尺寸与隐藏 + outline + 验证/条件格式/批注/超链接
                  + 表级设置（冻结、筛选、打印）+ 簿级设置（顺序、隐藏、tab 色）
  → 【新】单次写入器：逐表逐行一次成型 → save 一次
  → atomic_output_path 改名交付（现有，不动）
```

## 错误处理

- 排版计划计算或写入任何一步失败：抛错，原子交付保证不留半成品（现状语义不变）。
- 保留旧排版路径作为内部开关（环境变量/参数），用于金样对比和紧急回退；稳定一个版本周期后再考虑移除（移除另行决策）。

## 测试策略

1. **金样逐格对比**（对应验收标准 3）：新增对比工具，同一份表格数据分别走旧排版和新排版，逐格对比值、公式文本、字体、填充、对齐、边框、数字格式、行高、列宽、隐藏、outline、冻结、筛选、数据验证、条件格式、批注、超链接、合并、tab 色、打印设置、表顺序。5 个真实账户全部一致才算过。
2. **现有测试全绿**：`tests/` 70 个测试文件，其中 `test_紧凑输出`、`test_报告阅读布局`、`test_复核工作簿`、`test_全面独立复核文件与取消` 等直接触及排版结构（有 monkeypatch `_apply_report_presentation` 的用例），需要适配新结构但断言的业务语义不变。
3. **性能基准**：招商610301 账户（30 万行）端到端报告生成 ≤ 5 分钟；兴业131509 不慢于 28.9 秒基线。
