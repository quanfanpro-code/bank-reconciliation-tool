# 个人独立EXE设计

选择现有PyInstaller单文件方式，把本机默认JSON作为包内资源，GUI在冻结运行且资源存在时优先加载内置配置。此后沿用原校验、会话开关和开始核对配置。普通源码运行保持本机配置行为。

比较：外置JSON较容易修改但不满足单EXE写死；把密钥直接写入仓库源码会发布个人密钥；打包时从仓库外注入资源无需新依赖，可复用原流程，选用此方案。

数据流：仓库外个人配置→打包器资源→EXE内部→GUI原配置校验→原客户端。密钥值不出现在源码、命令参数、README或验证日志中。EXE所含资源可提取，此方式不提供秘密保护。

实现仅增加gui.py的包内配置路径选择，更新原打包cmd指定构建目录及数据文件。无内置文件的普通包回退本机配置，损坏配置沿用关闭及固定提示。

测试覆盖内置优先、无本机配置、源码不误读包内同名文件、损坏内置配置。实际成品在空白应用目录验证启动、模型和连接，并核验与本机密钥一致。构建及测试临时材料集中到本轮专属目录；成功后成品备份覆盖到真实桌面，清单核对后回收临时目录。

可逆：恢复备份的GUI和打包脚本，重新构建；不改变已有业务数据和算法。没有新增业务术语，不需要修改CONTEXT；此配置易于回退，不设ADR。
