# 筛选交互易用性设计

方案比较：
- 推荐沿用Tk/ttk，用一张条件清单、一个编辑区、现有列清单拖动。改动集中、便于测试、无新依赖，保留原筛选数据接口。
- 每项展开多个输入控件会使窗口过长；改成多步向导会增加点击，均不采用。

条件清单只存字段名和具体值，序列直接转换为FilterCriteria。包含文字全部满足，排除文字任一出现即排除，判断依据/业务类型/核对结果同类任一满足；不同类别同时满足。输入中的标点属于单条条件原文。选择清单行可修改，删除仅删除界面条件，不涉及文件。

将已有preview_filter的读报告与算预览拆成read_filter_report及summarize_filter，原preview_filter接口保持兼容。窗口选择文件后启动单个后台工作线程；重选只保留最新待办，给任务带报告版本编号，旧结果不进入新报告界面。内存只留当前报告数据；文件修改时间和大小变化后重新读取。计算和导出沿用原规则，正式导出仍读取源报告并另存。

列拖动共用现有重排方法，只改变列表顺序；拖到列表边缘可滚动，Alt+上下键和原按钮保留。界面采用当前标签页，不新增窗口链。报告选择、状态与底部按钮固定可见。

无难以回退的架构选择，不另建ADR。回滚使用修改前校验备份或版本历史；原文件及桌面EXE不改写。
