# 疑点分层处置设计（明显微小自动确认 + 中风险等距抽样）

日期：2026-09-06
对应需求：docs/requirements/2026-09-06-疑点分层处置-requirement.md

## 总体思路

两处改动，都在既有分流链路上做"后置处置"，不动候选生成与评分：

1. `route_candidate`（matching_policy.py）增加明显微小放宽分支；
2. 新增 `apply_medium_risk_sampling`（matching_policy.py），在差异池升级完成后对中风险候选做等距抽样标记，报告侧按标记改"建议动作"与统计。

## 一、明显微小零差额自动确认（route_candidate）

### 现状

`route_candidate` 把疑点原因统一收集进 `reasons`，`has_relationship_risk = bool(reasons)`，凡有原因即 `FLAGGED`（疑点事项）。候选歧义、低可信度、业务依据不足与文字冲突、边界不足等硬原因混在同一列表。

### 改动

把原因按"弱证据"与"硬冲突"分两组收集：

- 弱证据原因（可放宽）：候选歧义（`is_ambiguous`）、综合可信度低于门槛、业务依据不足。
- 硬冲突原因（不可放宽）：关键文字字段冲突、跨月多对多、仅日月总额缺边界、批次边界不足、完整组成缺跨双方闭合证据、总体资料尚未闭合（断档窗口/范围未知）。

新增分支，位于 `GROUP_RECONCILED` 分支之后、`total_diff_li > 0` 分支之前：

```
若 total_diff_li == 0
且存在弱证据原因
且不存在任何硬冲突原因
且 group_amount_li <= to_integer_li(config.clearly_trivial_threshold)
→ 返回 (AUTO_CONFIRMED, RiskLevel.NORMAL,
        "金额明显微小自动确认（原疑点：{原始原因合并}）")
```

风险等级取 `NORMAL`：差额为零，无可量化影响，与既有"金额完全一致且关系明确"的出口保持一致。这类候选不进月度差异池（差异池只归集 `total_diff_li > 0` 的自动归集事项），不会被池升级重新拉高，无需额外防护。

### 与 2026-08-09 规则的关系

旧规则"候选歧义必须挡住明显微小自动确认"在零差额且金额 ≤ 明显微小临界值范围内被本轮取代；超过临界值的候选歧义仍走 FLAGGED。旧设计文档为历史记录不改动，本条即取代声明。

### 截止性差异表不受影响（已读码验证）

`reporter.py:2256` "截止性差异"表来自 `_build_business_event_table()` 按业务链事件 `is_cross_period` 过滤，与候选 `processing_status` 无关。R1 只改候选状态，不触碰业务链事件，容差窗口内跨期的小额配对仍照常列示。

## 二、中风险等距抽样（apply_medium_risk_sampling）

### 插入点

`matcher.py` 的 `_commit_selected_candidates` 末尾、`apply_monthly_difference_pools`（matcher.py:2287）及其风险回填循环之后调用。必须在差异池之后：池会把累计超限的候选升级为高风险，高风险计数决定抽样样本量。

### 函数签名与逻辑

```python
def apply_medium_risk_sampling(
    candidates: list[MatchCandidate],
) -> dict[str, int]:
```

1. 抽样总体： `risk_level is MEDIUM` 且 `processing_status` 属于 {FLAGGED, AUTO_CLASSIFIED}（即会进入疑点事项表的全部中风险项）。
2. 样本量： `k = min(len(总体), 高风险候选数)`；高风险仅计 `RiskLevel.HIGH`，不含"范围未知"（按用户字面"和高风险的一致"）。
3. 排序：按 `min(bank_dates + journal_dates)` 升序；无日期的排末尾（真实候选两侧必有日期，仅防御）。
4. 等距选取：`step = n / k`，取索引 `floor(i * step)`，`i = 0..k-1`。`k >= n` 时全取；`k == 0` 时全不取。
5. 标记：`candidate.evidence["medium_sampling"] = "抽中待核查"` 或 `"未抽中留存备查"`；不改状态、不改风险等级。
6. 返回 `{"medium_total": n, "sampled": k}`，matcher 存入 `self.medium_sampling_stats`，供报告总览引用。

### 报告侧（reporter.py）

- `_build_issue_table`：中风险候选读取 `evidence["medium_sampling"]`：
  - 抽中：建议动作维持"结合摘要和期间优先核查"，判断依据追加"；中风险等距抽样：抽中（样本量=高风险笔数）"；
  - 未抽中：建议动作改为"等距抽样未抽中，随同低风险留存备查，本次不留人工"，判断依据追加"；中风险等距抽样：未抽中"。
  - 无标记（理论不出现）：维持原建议动作。
- 总览统计区（reporter.py 约 1850 行风险计数行之后）新增两行："中风险抽样总数"、"中风险抽中待核查数"，数据来自 `matcher.medium_sampling_stats`，缺省不显示。
- 列结构不变，不新增列，避免影响既有读取方与测试。

## 三、不改动清单

- 不新增配置项、不新增业务状态（沿用"自动确认"）。
- 高风险、范围未知处置不变；银行侧/日记账侧待查表不变。
- 差异池归集与升级逻辑不变。
- 2026-08-09、2026-09-05 旧文档为历史记录，不改写。

## 四、测试要点（TDD）

新测试文件 `tests/test_疑点分层处置.py`：

1. 零差额 + 组金额 ≤ 临界值 + 仅弱证据原因 → 自动确认，依据含"金额明显微小自动确认"。
2. 零差额 + 组金额 > 临界值 + 仅弱证据原因 → 维持疑点。
3. 零差额 + 弱证据原因 + 文字冲突/断档窗口 → 维持疑点。
4. 中风险 n 笔、高风险 h 笔 → 抽中 min(n, h) 笔；抽中索引等距（按日期排序后 floor(i·n/k)）。
5. 高风险 0 笔 → 抽中 0 笔，全部标记"未抽中留存备查"。
6. 池升级为高风险的候选计入高风险基数。

受取代规则影响的旧测试（test_reliability_upgrades.py、test_automation_first.py 中"候选歧义必须疑点"的断言，若其金额 ≤ 5,000）按新口径调整：金额调到临界值之上继续验证旧规则，或改断言新行为；逐个核实后处理并在审查报告说明。

## 五、残余风险（向用户披露）

- 容差窗口（31 天）内跨期的小额配对会被自动确认，跨期信号改由"截止性差异"表独立承担。
- 候选歧义在 5,000 元以下不再挡自动确认，同一金额的重复往来若真实串户，程序不再提示。
- 中风险未抽中项仍列示但默认不核查，属抽样风险，与审计抽样同理。
