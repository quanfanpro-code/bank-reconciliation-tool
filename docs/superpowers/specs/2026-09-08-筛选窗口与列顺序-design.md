# 筛选窗口与列顺序设计

选择沿用已有Tk窗口、筛选后端与openpyxl报告；不增加依赖。全新筛选引擎会重复已有整项筛选机制，直接搬移已生成报告的列会牵涉跨表公式，均不采用。

底稿筛选.py扩充FilterCriteria；从核对明细或旧版匹配组成读取单笔金额，以稳定事项编号将命中原始行投回整项。旧版带收支方向的绝对金额先恢复统一带符号值。整组使用已有组金额口径，覆盖比例在其他条件筛选后的总体上继续计算。

新增筛选窗口.py：集中条件、日期选择、金额口径、条件预览与后台数量预览。保留现有后台导出和15秒心跳。列顺序设置在同一窗口的标签页，按表上下移动列；独立保存，不要求先完成一次导出。

新增报告偏好.py：在本机应用目录存JSON偏好，读取时忽略已消失列并补上新列。Reporter在写工作簿前重排数据表，既有按表头定位的公式生成链自然引用新列。隐藏身份列保留；核对编号仍固定靠前。

验证：构造金额边界和工资批次；用真实报告入口生成Excel，再用本机Excel重算人工选择；检查原文件哈希、组成和公式。旧报告无金额筛选时沿用现有行为。

回滚：修改前146个受版本管理文件已逐个备份校验，并保存完整Git bundle。新代码独立分支，恢复备份或回退该提交即可；用户报告不覆盖。

用户追加要求：列顺序只影响展示，不决定字段身份。统一按报告首行列名识别，容忍列换序、额外列和两端空格；重复列名及必要列缺失必须明确提示。Excel移动列并填写人工意见后，预览、筛选、意见、备注和公式结果必须正确，源文件不能被改写。
