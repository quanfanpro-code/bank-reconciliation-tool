# 列识别方案

建议沿用已确认的顺序，由程序公共入口在读完原表后生成、按证据验证并确定映射。先按列的完整含义划分能用的字段，再用实际值判断列是否有效。对仍能承担同一角色的金额列和余额列，用同一份表的余额变化来区分。两个来源的文件名、原表本方字段或账户元数据相互矛盾时停止该户。

只给旧列表增加优先级成本较低，但无法可靠处理近义列、两套金额口径和已经保存的错误映射。按银行逐个写固定布局只覆盖当前模板，同一家银行换导出格式后仍存在风险。共用识别器使两个入口依赖同一份行为和回归测试。

保留原有程序匹配和报告逻辑。GUI 读取后展示识别结果和歧义，人工选择后重新验证。Skill 的命令入口直接使用公共流程，返回文件、字段、候选列与理由，交给当前 Agent 用提问界面向用户确认后补跑。旧映射模板只提供有效的人工配置，历史自动映射必须重新判断。两列内容在有关行完全相同时按一种证据处理，列顺序不参与打分。
