# 报告阅读与人工复核展示设计

## 方案比较与选择

1. 只隐藏旧表：代码少，但无法做到一对一并排及整组展开，不能满足已确认需求。
2. 复用现有结果，增加阅读展示并统一排版：保留原计算链、身份和原始数据，改动集中在报告输出和筛选展示。采用本方案。
3. 重写匹配和复核流程：超出用户边界，禁止实施。

## 数据流与界面

既有匹配结果 → 既有复核事项/原始明细/人工候选 → 展示投影 → 原有人工公式 → 展示引用与Excel原生折叠。新增“报告展示.py”只负责现有数据的列选取、阅读分组、格式及引用，不介入匹配和风险判断。

逐笔核对每行左右各一条原记录。整组核对每组主行显示双方笔数、各自收入/支出、两种差额及原有依据，子行先银行后序时账。汇总金额放在带说明的文字格，原始金额单独使用收入/支出数值列；一个组成行只能出现一侧金额。主行按既有事项号引用当前结论，组成按原始记录号引用当前去向。

人工全查/抽样保留唯一主行和填报编号、原有下拉选项、现有生效逻辑；改善主行和组成排版，替代方案在本事项下展示，替代金额作为说明文字，不能混入原始金额列。展示表仅链接到唯一填写入口。辅助技术列隐藏。筛选只适配表名和整项行显示，不改筛选条件算法。

月度表重排现有列，把收支和月末余额放在前部；缺失余额显示“缺失”，年合计只加总发生额。范围说明和原始异常提示继续留在结论和隐藏输入检查中。

## 错误与兼容

否定、替代、冲突仍用原公式；展示保留初始分组但显示当前记录结果，不把原分组当成当前已确认关系。空表保留表头，不制造0金额原始记录。旧版报告的筛选保持兼容。组折叠用Excel原生功能，不增加宏。

## 验证与可逆性

先写导出工作簿行为测试并观察失败，再实现；运行既有月度、人工计算、筛选测试及全量回归。用真实Excel重算、导出页面查看默认汇总与展开组成。对比计算文件字节和修改前业务表指纹，保留修改前备份。只提交展示范围文件；不做不可恢复删除，不改变后端算法。布局容易回退，无须新增架构决策记录。
