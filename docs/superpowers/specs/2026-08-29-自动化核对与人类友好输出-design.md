# 自动化核对与人类友好输出设计

## 目标

在保留现有读取、标准化、候选生成、整数金额精度和原始行追溯能力的基础上，把工具改造成“自动运行到底、自动形成结论、按重要性揭示疑点”的银行流水核对工具。报告首先服务财务和审计人员阅读，机器编号、评分细项和运行记录继续保留但默认隐藏。

## 总体原则

1. **不中断**：只要仍存在可计算的有效交易，业务疑点不得中断运行或阻止报告生成。
2. **不甩给人**：每一项必须有系统状态、风险等级、判断依据和建议动作，不以“待人工复核”代替程序判断。
3. **不虚构**：不能唯一确定逐笔关系时，不强行选择一个看似最可能的答案；能够整体闭合时输出整组勾稽结论。
4. **看重要性**：可量化疑点统一使用明显微小错报临界值、实际执行重要性水平和累计差异池分级。
5. **技术失败才停止**：只有文件无法读取、无法识别日期金额或没有任何有效交易等客观上无法计算的情况允许失败退出。

## 方案比较

### 方案 A：所有歧义和冲突强制人工处理

- 做法：唯一一对一以外的组合、字段冲突、跨期和范围问题全部进入人工清单。
- 优点：规则表面上最保守。
- 缺点：自动化率低，把程序能够量化和归集的工作推给用户；不符合本工具目标。
- 结论：不采用。

### 方案 B：保留现有业务规则，只改 Excel 可见性

- 做法：隐藏候选ID、评分、大模型记录等技术列，调整工作表顺序和格式。
- 优点：改动最小。
- 缺点：小额阈值仍可能被当成配对依据，日月合计仍可能冒充逐笔匹配，伪余额和误导性指标仍然存在。
- 结论：不采用。

### 方案 C：自动确认、整组勾稽、重要性分流三层结果（采用）

- 做法：确定关系自动确认；多个答案但封闭组完全闭合时自动形成组级结论；其余疑点按影响金额和累计池自动分级。所有状态都由程序完成，人工标注仅为可选后续信息。
- 优点：自动化率高，不虚构逐笔关系；复用现有候选、差异池和报告架构；无需新增依赖。
- 风险：结果状态比现有“自动确认/待复核”两类更多，需要同步重做汇总口径和测试。
- 结论：采用。

## 领域结果模型

### 关系结果

每条记录最终进入且只进入以下一种关系结果：

1. **逐笔自动确认**：唯一的一对一关系，金额、方向和必要的范围证据成立。
2. **唯一组合自动确认**：唯一的一对多、多对一或多对多关系，双方收入、支出分别闭合。
3. **整组勾稽一致**：存在多个合理逐笔组合，但候选图中的整个交易组完全闭合；只确认组级关系。
4. **自动归集差异**：已形成关系或可量化范围，但存在非零金额差异、字段冲突或已知缺口。
5. **银行侧待查**：银行侧记录未进入逐笔或整组结论。
6. **日记账侧待查**：日记账侧记录未进入逐笔或整组结论。
7. **范围受限**：账户、币种、期间、人口或解析异常影响整体范围，但程序已经完成可用数据处理。

“关系结果”描述程序已经完成什么，不包含“等待用户”状态。

### 风险等级

每个关系结果可以同时带一个风险等级：

- **正常**：金额完全闭合且没有需要揭示的范围或字段疑点。
- **低风险**：影响金额不超过明显微小错报临界值，且所在累计池也未超过该临界值。
- **中风险**：超过明显微小错报临界值，但单项和累计均未超过实际执行重要性水平。
- **高风险**：单项或累计超过实际执行重要性水平，或者命中明确的定性高风险规则。
- **范围未知**：影响无法量化、总体人口无法闭合或核对对象身份存在冲突。

高风险和范围未知仍然是程序的完整输出状态，不要求人工填写后才能生成报告或结束运行。

## 影响金额口径

重要性水平不能直接使用一个模糊的“差额”字段，不同疑点按以下口径量化：

| 疑点类型 | 影响金额 |
| --- | --- |
| 非零匹配差异 | 双方组金额差异的绝对值 |
| 多个候选且组未闭合 | 竞争记录双方绝对金额合计取较大值 |
| 关键字段冲突 | 冲突候选双方绝对金额合计取较大值 |
| 银行侧或日记账侧单边项 | 单边记录绝对金额 |
| 可识别金额的解析异常 | 原始金额绝对值 |
| 已知期间缺口 | 缺口记录绝对金额合计 |
| 金额无法识别或人口未知 | 无法量化，风险等级为“范围未知” |

收支不得净额抵销。累计池按自然月、来源侧、收支方向和疑点类型分别归集，避免一类问题抵销另一类问题。

## 自动核对数据流

```text
读取并识别表格
  → 标准化日期、方向、金额、摘要和原始行号
  → 核对对象与人口完整性检查
  → 生成一对一、组合、连续摘要、日汇总和月汇总候选
  → 构建候选竞争关系
  → 唯一关系自动确认
  → 封闭候选组自动形成整组勾稽
  → 剩余单边、冲突、差异和范围问题计算影响金额
  → 单项与累计池重要性分级
  → 生成系统结论、疑点、建议动作和技术追溯
  → 输出人类友好 Excel
```

## 候选与封闭组设计

### 唯一关系

- 一对一、一对多、多对一和多对多使用同一套唯一性判断，不因组合笔数自动降低为人工状态。
- 金额完全相等是确认关系的重要证据；金额存在差异时只形成候选和差异归集，明显微小临界值不得单独创造配对关系。
- 同一记录只允许被一个逐笔或唯一组合结果占用。
- 大模型只能补充文字支持或冲突证据，不能创造候选、改变金额或覆盖分流规则。

### 多个合理答案

- 组合搜索至少识别“只有一个解”还是“存在多个解”，不再找到第一个解就假定唯一。
- 对竞争候选构建相互连通的交易组。
- 若交易组覆盖的银行记录和日记账记录在收入、支出两个方向分别完全相等，且没有未纳入的组内记录，则自动输出“整组勾稽一致”。
- 组级结论保留全部组成记录和候选依据，但不选择虚假的逐笔对应关系。
- 交易组不能闭合时，保留程序评分最高的建议关系供阅读，同时把未闭合影响金额按重要性水平分级；程序仍然结束并生成报告。

### 日总额与月总额

- 日总额、月总额分别闭合时可以自动形成“日总额勾稽一致”或“月总额勾稽一致”。
- 这两类结果计入自动完成率和组级勾稽率，不计入逐笔精确匹配率。
- 组内记录继续保留在组成明细中，不再显示为已经建立逐笔对应。

## 特殊业务场景

### 手续费和利息

- 银行侧单独出现的手续费、利息、结息记录自动分类为“建议补记或核实”的单边事项。
- 若净额到账与手续费能够组成唯一闭合组，自动形成唯一组合或整组勾稽结果。
- 金额按单项和累计池分级，不要求用户逐笔确认后程序才能完成。

### 冲正、退汇和重新入账

- 根据相反方向、相同或关联金额、相近日期和文字证据形成业务链。
- 能够闭合的业务链自动形成组级结论；不能闭合的剩余影响进入疑点分级。
- 不允许仅凭正负净额为零就隐藏未解释记录。

### 跨日、跨月和期末截止

- 跨日或跨月本身不强制改变为人工状态；有唯一关系或封闭组时仍自动完成。
- 期末前后跨期、缺少参考号或存在反向冲销时增加风险证据，最终按影响金额和定性规则升级风险等级。

### 核对对象和人口范围

- 账号、币种明确不一致或单份文件混有多个值时，程序继续处理，但首页输出最高优先级范围疑点。
- 账号、币种字段不存在时标记“身份未完全验证”，不要求用户补录后才能运行。
- 解析失败金额已知时进入重要性池；金额未知时形成“范围未知”。
- 所有原始行必须归入有效交易、排除行或解析异常，首页展示人口去向勾稽。

## 余额核对设计

- 只有至少一侧存在有效余额且能够确定期初口径时才计算对应的余额连续性；两侧比较需要双方都有可靠余额。
- 没有余额时输出“余额核对未实施”，不生成从零起算的差异明细。
- 两侧余额差额为零时不生成异常记录。
- 差异类型只表达事实：发生额不一致、余额差异、连续性不成立、数据不足；不直接使用“金额错误”“时间序错误”等调查结论。

## Excel 报告设计

### 工作表顺序

1. `核对结论`
2. `疑点事项`
3. `自动归集事项`
4. `银行侧待查`
5. `日记账侧待查`
6. `逐笔匹配`
7. `整组勾稽`
8. `匹配组成`
9. `输入检查`
10. `月度统计`
11. `每日统计`
12. 按数据情况生成的余额工作表
13. 默认隐藏的技术工作表

### 核对结论

首页最多保留约十五项核心内容：

- 核对对象、币种和期间；
- 原始行、有效交易、排除行和解析异常的人口勾稽；
- 逐笔自动确认、唯一组合、整组勾稽、自动归集、两侧待查的笔数和金额；
- 低、中、高、范围未知疑点的笔数和影响金额；
- 余额核对状态；
- 总体系统结论和前三项建议动作。

技术运行指标、模型调用统计、候选阶段分布和内部池编码移到隐藏技术区。

### 疑点事项

默认可见列不超过十五列，顺序为：

1. 系统结论；
2. 风险等级；
3. 疑点类型；
4. 建议动作；
5. 影响金额；
6. 累计池金额；
7. 银行日期、金额、摘要；
8. 日记账日期、金额、摘要；
9. 判断依据；
10. 稳定匹配ID或事项ID；
11. 可选后续状态和说明。

可选人工标注不得排在最前面，也不得存在默认“未复核导致报告未完成”的逻辑。

### 默认隐藏规则

- `运行参数`、`大模型辅助明细`整张工作表默认隐藏。
- 候选ID、匹配阶段、金额分、日期分、文字分、结构分、差异池ID、模型请求信息和内部状态列默认隐藏。
- 稳定匹配ID、事项ID、原始行号、日期、金额、摘要、系统结论、风险等级和建议动作默认可见。
- 原始未映射列继续保留在两侧待查表中，但默认隐藏，只把标准化业务字段放在前面。
- 解析异常使用固定中文列，原始字典和内部追踪字段默认隐藏。

### 阅读格式

- 支出金额一律显示为正数，净额显示真实正负方向。
- 金额使用 `#,##0.00`，笔数使用整数，比例使用百分比。
- 程序结果使用黑字；可选人工标注区域使用浅色底纹。
- 差异为零使用普通样式，非零差异按低、中、高风险使用逐级加深的黄、橙、红色，不按正负数判断好坏。
- 摘要、依据、建议和说明启用自动换行并限制合理列宽。
- JSON 辅助文字改为“字段：内容；字段：内容”。
- 关键列和首行冻结，筛选、下拉和公式注入防护继续保留。

## 可选人工标注

- 报告首次打开时已经具有完整系统结论，不需要任何人填写才能使用。
- 用户愿意补充时，可以填写后续状态、处理说明、调整凭证号、责任人和日期。
- 首页可以用普通 Excel 公式额外展示后续处理进度，但该进度不改变程序运行状态。
- 不使用宏、不新增插件、不要求把报告重新导回程序。

## 最小实现边界

优先复用现有共同入口，不建立新框架：

- `input_precheck.py`：补充核对对象、人口去向和范围疑点，不把业务疑点变成技术阻断。
- `matcher.py`：识别组合是否唯一，构建封闭交易组，保留现有候选生成阶段。
- `matching_policy.py`：把候选关系判断与重要性风险分流分开，复用现有金额结构、文本证据和差异池。
- `balance.py`：修复无余额、零差异和无依据定性。
- `reporter.py`：集中生成新的业务视图、隐藏技术列、修正金额口径和样式。
- `gui.py`：仅在现有参数说明和完成提示确有需要时做最小文字调整，不新增复杂交互。
- 不改通用 `make_excel.py` 的全局行为；报告专用样式在 `Reporter.generate_report` 的现有后处理阶段完成，避免影响其独立命令行用途。

不新增依赖，不建立数据库，不开发新的配置系统或全局优化器。

## 错误处理

- 文件无法打开、表头无法识别、日期金额完全不可用或没有任何有效交易时，给出明确技术错误；这是唯一允许不生成正式报告的情形。
- 其他输入异常均尽量生成受限报告，记录已处理范围、未处理原因和风险等级。
- 报告生成失败不得覆盖原始文件，临时输出失败时保留清楚错误信息。
- 所有写入 Excel 的文本继续经过公式注入防护。

## 测试策略

### 业务规则

- 唯一一对一、一对多、多对一和多对多均自动确认。
- 两个以上替代组合形成封闭组时自动整组勾稽。
- 多解且未闭合时仍输出系统建议、影响金额和风险等级，不产生强制人工状态。
- 日/月总额闭合计入组级勾稽，不计入逐笔精确匹配。
- 明显微小、介于双阈值之间、单项超限、累计超限分别得到低、中、高风险。
- 账号币种冲突、字段缺失、可量化缺口和不可量化缺口均继续生成对应受限结果。
- 手续费、利息、净额结算、冲正和跨期样例覆盖自动分类与风险分流。

### 余额与统计

- 没有余额不生成伪余额差异。
- 差额为零不输出异常。
- 同一笔支出在汇总、每日、月度和明细中均显示正数，净额保持负数。
- 精确匹配率、组级勾稽率、自动完成率和疑点率口径互不混淆。

### Excel 成果

- 机器字段仍存在但默认隐藏，稳定ID和原始行号可见。
- `运行参数`和`大模型辅助明细`默认隐藏且可人工取消隐藏。
- 疑点表打开即可看到系统结论、风险、依据和建议，不依赖人工填写。
- 金额、笔数、百分比、颜色、换行、冻结和筛选均符合设计。
- 人工完全不填写时首页结论完整；自愿填写后处理信息时进度公式更新。
- 公式注入防护、数据验证和工作簿打开完整性不回归。

## 独立复核后的补充设计

- **空余额共同根因：** `BalanceRecalculator.recalculate()`在判断可用余额时先排除空值和空字符串，再调用金额解析；报告层同时只在双方均有可用余额时构造余额差异表，形成双重保护。
- **交易金额展示：** 标准化金额继续保留正负号参与计算；仅在“匹配组成”业务视图中输出绝对金额，并新增“收支方向”。这样既满足人类阅读，又不改变底层计算口径。
- **首页金额口径：** 每个匹配组只按一次组金额汇总，不把银行侧和日记账侧重复相加；自动确认、整组勾稽、自动归集、疑点和高风险分别统计组金额。
- **后续进度联动：** 首页预留四个进度项目，工作簿生成后写入 `COUNTBLANK` 和 `COUNTIF` 公式，引用“疑点事项”的“后续状态”列。疑点表只有表头时公式返回零；不使用宏或新依赖。
- **外来表头安全：** 报告专用 `_safe_table()`同时清理列名和单元格文字，避免修改通用 Excel 生成器；程序内部固定表头不受影响。
- **零影响风险：** 风险函数先处理范围未知和定性高风险，再把非正影响归为“正常”，其余金额才进入低、中、高三级阈值判断。
- **最小清理：** 删除无调用方的旧汇总表和旧待处理表函数，保留公开回调参数和两侧待查的原始业务字段，避免无必要的兼容性破坏。
