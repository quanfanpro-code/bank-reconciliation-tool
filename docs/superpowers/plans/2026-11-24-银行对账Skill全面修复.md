# 银行对账技能全面修复实施计划

本次基线为 `e5ae8d4`。每户以两份表完成核对，写入现有六张工作表。复用技能包内的 Python 入口和引擎。范围及验收编号见[需求](../../requirements/2026-11-24-银行对账Skill全面修复-requirement.md)，读表、配对和出表的分工见[设计](../specs/2026-11-24-银行对账Skill全面修复-design.md)。

用隔离检出目录实施。每组先把复核样例变成失败测试，再改最少的现有代码，重跑当组和受影响测试。改动已有文件前保留原编码，备份并比对内容。本文的引擎文件都在 `.agents/skills/bank-reconciliation-agent/scripts/engine/`，技能入口是同级 `scripts/运行核对.py`。

## 第 1 组 · 读到哪页、哪行、哪户

对应 1、2、3、4、5、10、21。主要文件为 `直读XML.py`、`input_precheck.py`、`data_loader.py`、`列识别.py`、`银行核对入口.py` 和 `application.py`。

- [ ] 在 `tests/test_Skill全面修复输入.py` 断言同户续页全部被计入，汇总页仅供校验。换页顺序时银行仍读入 3 笔，9 万元支出定位到实际页和行。用 CSV 的空行和 Excel 1904 日期系统分别验证实际行号和日期。
- [ ] 在同一测试文件验证：两对普通文件名凭表内账户自动配户，前导零保留。文件名写 222、表内写 111 时，导出归属 111。缺配乙户仍出甲户报告。明确零交易的银行 Excel 与账上 100 元收款仍能对出差 100 元。
- [ ] 在同一测试文件验证本方账号一致而对方账号不同。给同一批交易使用两套词表未收录的等义表头并重新排列列。断言 Agent 在读表阶段获得两份原表，回复含原列名和用途，程序按原行验证后给出相同的收支与选配结果。
- [ ] 在匹配之前接通 Agent 的读表步骤。用现有读表代码给出工作表、原行、查询范围、原列及内容样例，现有列识别提供建议。Agent 解释字段并通过现有列映射参数或复核交接提交，程序验证并自动继续。同步处理程序原先会静默漏掉的订单、对方账号等字段。按各页内容识别同户续页，保留明示零交易的结构信息。批量按表内身份处理重复导出和缺配户，验收一次运行能够完成各户已有的核对工作。
- [ ] 运行新增输入测试、`test_列身份识别.py`、`test_银行核对入口.py`、`test_共享公式读取.py` 和 `test_阶段一终审报告范围口径.py`。预期全部通过，零交易和批量用例回读实际 Excel。

- [ ] 在 `tests/test_Skill全面修复金额.py` 用参数化测试输入三份等价格式。双方均收入 100、支出 100、末笔余额 1,000。保留真的红字冲回测试。另测一行收入 160、支出 60 时，两列分别进入报告。
- [ ] 在同一文件断言 USD 100 与 CNY 100 不相配。构造两个金额格异常的样例，一个可从同笔原行和余额复算，一个原件确实没列明金额。前者应重新计入并对账，后者应列出该原行和实际已算金额。
- [ ] 复用现有数字解析。识别试算和正式解析走同一方向换算。保存原收支、明确币种和余额用净变动，供现有汇总、范围比较及匹配使用。
- [ ] 运行新增金额测试、`test_收付分列回归.py`、`test_data_direction_and_fields.py`、`test_阶段一金额口径声明一致性.py` 和 `test_阶段一金额缺失边界.py`，预期全部通过。

## 第 3 组 · 核清是哪一笔

对应 11、12、13、14、15、16、20。主要文件为 `运行核对.py`、`matcher.py`、`业务事件.py`、`业务分组.py` 和 `复核事项.py`。

- [ ] 在 `tests/test_Skill全面修复匹配.py` 比较同订单退款与异订单退回。异订单两边差额各 10 万元，同订单仍能确认。五笔增为六笔时，原文唯一对应的 15 万元仍自动确认。
- [ ] 在同一文件验证工资相差 29 天，容差 31 天可确认，3 天和零天不确认具体原行。用 7,000＋3,000 和 6,000＋4,000 两种组合检验 10,000 元合笔。给前一组添加原表可核实的同一订单号时，应选前一组。证据相同时由程序稳定选定一组。加入 27 条无法参与的记录或打乱顺序，采用的原交易不变，任何原行最多使用一次。两种配法完整覆盖同一批原行时可确认整组。
- [ ] 在同一文件增加金额相同但交易日不同、金额和日期相同但摘要用途或所属月份不同的对照。断言比较后选定正确原行，工作簿只有一套采用结果。首次 Agent 答复超时时，断言技能自行重组并重试该组，仍能用日期、金额和原文继续核对。已核实的用途冲突在后续超时时保留。用缺页期间的弱摘要和余额复现错误锁定，断言程序另外查业务证据、在符合条件的配对中选定一套并保留期间限制。重复流水号带到结果，保留各原行。
- [ ] 共用已有订单检查、候选原文核验和日期限制。按双方原行复用已核实的用途。使用已有搜索截断信息查找仍可能的组合。复用 `matcher.py` 的 `select_non_conflicting_candidates` 比较整组配对，沿用业务证据排序并补足同等条件时的稳定取舍。在现有结果表输出选定关系和实际剩余差额。
- [ ] 运行新增匹配测试、`test_异常优先核对.py`、`test_Agent与核对闭环.py`、`test_待办误分复查.py`、`test_余额断档局部降级.py` 和 `test_第二阶段组合搜索预算.py`。测试断言最终配对与处置。

每组测试先得出与需求中同样的失败，再改代码并确认通过。以合成原表跑单户及双目录命令，复算现有六表中的原行、收支、期间和余额。使用正常单位、日期、符号与已知反例验证，另用未用于定位缺陷的新表头排列作为格式对照。

把陌生表头、同分的配对、Agent 超时、缺一个账户的文件、出现大额差异放进完整入口验收。回读程序返回值和 Excel，确认技能自己完成选配、差异计算及出表。断言无要求用户选列、挑配对、补材料、手动重跑或按金额派发的任务。复核保留下来的人工入口，逐项验证它确实属于现有两表已查尽、异常重大且后续需要用户权限或业务决定的情形。
