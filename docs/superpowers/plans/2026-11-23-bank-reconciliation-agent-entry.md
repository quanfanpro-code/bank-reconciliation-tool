# 银行流水核对 Skill 实施计划

> 逐项串行执行。每项先验证失败，再做最小实现并复测。

**目标** 让运行 Skill 的 Agent 用问答取得核对设置，调用修复后的程序核对单户或批量账户，交付相同的五表报告。

**方案** 共用 `application.run_reconciliation`。独立命令入口只负责把答案转换成文件、目录和核对设置。需要文字判断时，现有候选评估接口向本次 Agent 交接候选。用户侧只有提问和最终交付。

**环境** Windows 和现有 Python 项目依赖。使用当前 Agent 的提问能力和既有 Excel 生成流程。无独立模型 API 和新增 Python 依赖。

**已确认方案** `docs/superpowers/specs/2026-11-23-bank-reconciliation-agent-entry-design.md`。

## 1. 文件配对和核对入口

修改位置为项目中的 `银行核对入口.py` 和 `tests/test_银行核对入口.py`。入口接受两文件或两目录、输出目录、明显微小错报临界值和实际执行重要性水平。继续复用列识别和 `run_reconciliation`。

- [ ] 写测试。目录中用同一公司、银行、前导零账号的两个文件配成一户。历史报告排除。重复来源和缺少一侧各有单独结果，其余账户仍能执行。
- [ ] 运行 `python -m pytest -q tests/test_银行核对入口.py`，新入口不存在时测试应失败。
- [ ] 用文件名中的公司、银行和完整账号建立配对键。找到同户两边唯一文件时才执行。单户入口读取指定文件，核对结果中保留读取失败原因。每户独立记录输出路径，原表只读。
- [ ] 重跑测试。用同一文件对分别走单户和目录入口，对照原行数、日度和月度数以及五张工作表。

## 2. 当前 Agent 判断剩余候选

在 `银行核对入口.py` 实现 `AgentReview.evaluate_candidates(request)`。启动核对时关闭独立模型配置，通过 `matcher_ready` 接入评估器。

- [ ] 添加测试。合法答复只能选本次发出的候选编号。返回其他编号、无效内容、弃选或超时时，沿用现有本地判断。测试验证候选编号、理由和结果。
- [ ] 在本次任务的独立目录里写候选内容。用唯一请求编号关联本次 Agent 的答复。Agent 返回候选编号、文字判断和理由。程序检查候选范围并复用原本的收支、金额和原始行占用校验。候选中文字按原表证据解释。
- [ ] 执行一次含真实歧义的验证。确认能在后台等待当前 Agent 的答复，确认无歧义交易不会触发这个交接。

## 3. 提问和交付

在新 Skill 的 `SKILL.md` 写明问答方式、文件对及批量入口和回传规则。Skill 源码单独保存，按用户技能目录规则放置并验证可用入口。

- [ ] 第一轮只问已经缺少的关键信息。需要选项时优先用提问界面，路径可自由填写。已知单户或批量模式、文件和参数时直接复用。
- [ ] 需要用户决定同一账号该用哪份文件时，通过提问列出具体文件。匹配候选的业务文字由当前 Agent 判读。运行参数由 Agent 填写。
- [ ] 从用户视角验收单户、批量、同户冲突和实际输出回读。确认没有 API 配置问题，也能独立打开月度和日度核对。
- [ ] 运行技能格式或安装验收。只提交与 Skill 相关的代码和通用说明。向用户说明实测结果及任何尚未通过的验收。
