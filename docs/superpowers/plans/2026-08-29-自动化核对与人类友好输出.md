# 自动化核对与人类友好输出实施计划

> **For agentic workers:** 用户未授权子 agent 实施；读取 `executing-plans.md` 后按本计划串行执行。每一步使用复选框跟踪。

**目标：** 让工具在业务疑点存在时仍自动运行到底，使用重要性水平自动分级，并生成默认面向人阅读、技术记录默认隐藏的 Excel 核对成果。

**架构：** 保留现有“输入预检查 → 候选生成 → 统一评分与分流 → Reporter 输出”主链。把候选关系与风险等级拆成两个正交维度，在现有候选竞争组上增加“封闭组”判断，并在 `Reporter.generate_report` 的现有后处理阶段集中完成报告可见性和样式，不引入新框架或依赖。

**技术栈：** Python 3.11+、pandas、openpyxl、numpy、CustomTkinter、pytest。

## 全局约束

- 仅处理一份银行流水及其对应的一份银行日记账，不合并多个账户。
- 业务歧义、字段冲突、范围限制和重大事项不得中断运行或等待人工填写。
- 每一项必须具有系统结论、风险等级、判断依据和建议动作。
- 明显微小错报临界值与实际执行重要性水平负责风险分级，不得单独证明交易身份。
- 用户完全不填写可选人工标注时，报告也必须完整可用。
- 原始输入文件只读；不得覆盖银行流水和日记账。
- 不新增运行依赖，不修改 `make_excel.py` 的通用行为，不开发宏、数据库或报告回传。
- 所有中文 Markdown 使用 UTF-8 with BOM；代码修改使用局部补丁。
- 完整备份位于 `C:\Users\27651\BackUp\银行流水核对工具_20260829_124630\`，81个文件哈希校验一致。
- 不执行 Git 提交、推送、合并、清理或删除操作，除非交付阶段另获授权。

```python
class ProcessingStatus(str, Enum):
    AUTO_CONFIRMED = "自动确认"
    GROUP_RECONCILED = "整组勾稽一致"
    AUTO_CLASSIFIED = "自动归集事项"
    FLAGGED = "疑点事项"
    NO_CANDIDATE = "未找到候选"


class RiskLevel(str, Enum):
    NORMAL = "正常"
    LOW = "低风险"
    MEDIUM = "中风险"
    HIGH = "高风险"
    UNKNOWN = "范围未知"
```

`MatchCandidate`、`DifferencePoolResult` 增加 `risk_level: RiskLevel`；`DifferenceComponent.included_in_pool_review` 改为 `included_in_risk_pool`。`route_candidate` 使用以下顺序：

1. 没有差异、歧义、冲突和跨期风险：`AUTO_CONFIRMED + NORMAL`；
2. `evidence["resolves_full_group"]`：`GROUP_RECONCILED`；
3. 有非零金额差异：`AUTO_CLASSIFIED`；
4. 其他歧义、冲突或范围疑点：`FLAGGED`；
5. 风险等级按影响金额与双阈值计算，状态不因高风险变成人工等待。

## 主要风险与控制

- **组合搜索性能：** 只保留最多两个不同解来判断唯一性，找到第二个立即停止，不穷举所有组合。
- **封闭组误吞逐笔结果：** 只有包含歧义候选且收入、支出分别完全闭合的竞争组才生成合成候选；普通日/月总额候选不抢占明确逐笔关系。
- **重要性误用：** 影响金额按疑点类型单独定义，未知金额不得按0处理。
- **报告兼容性：** 明确不兼容旧工作表名称和列顺序，但稳定ID、原始行号及技术字段不删除。
- **人工依赖回潮：** 测试全文搜索“待人工复核、必须人工、未复核所以未完成”，生产输出不得出现这些状态。
- **通用 Excel 引擎受影响：** 不修改 `make_excel.py`，所有报告专用样式集中在 `Reporter` 后处理。
