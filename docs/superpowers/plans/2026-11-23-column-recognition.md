# 列识别实施计划

需求见 `docs/requirements/2026-11-23-column-recognition.md`，方案见 `docs/superpowers/specs/2026-11-23-column-recognition-design.md`。桌面版先回归通过，再验收 Skill。

1. 先把实测失败样本写成测试并运行。包括角色混淆、换序、显式账户冲突、余额对候选金额的区分和无法判定只暂停一户。
2. 在 Python 公共入口增加同一套整表字段识别和复核。桌面读表和映射对话框使用共享结果，已有人工映射进入同一验证。测试在开始匹配前检查账户、日期、收付和余额角色。
3. Skill 用公共入口、结构化返回字段冲突。用户用提问界面选定字段后增量补跑。保留其他账户的结果。验证没有从错列形成报告，也没有把交互退回给用户跑命令。
4. 复跑真实数据，检查原始行归属、金额、两种入口结果；更新 README 和验收记录。测试通过后仅提交程序、Skill 和相关文档并推送。
