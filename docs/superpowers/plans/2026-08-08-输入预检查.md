# 银行流水核对输入预检查实施计划

> **For agentic workers:** Read `subagent-driven-development.md` when the user authorizes subagents; otherwise read `executing-plans.md` and implement task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有一份银行流水与一份银行日记账的核对流程前增加自包含输入预检查，并把实际检查结果写入最终 Excel。

**Architecture:** 新建 `input_precheck.py` 集中保存表格结构识别、检查结果模型和八项业务检查；`DataLoader` 复用该结构结果读取一至三行表头；`application.py` 在创建匹配器前统一执行检查，GUI 只展示分级结果，`Reporter` 只负责把同一份结果写入报告。

**Tech Stack:** Python、pandas、openpyxl、customtkinter、pytest；不新增第三方依赖。

## Global Constraints

- 一次只处理一份银行流水和与其对应的一份银行日记账。
- 不合并多银行流水，不从完整序时账筛选 `1002` 或“银行存款”。
- 不在运行时调用 `complex-table-header` Skill；相关原则必须固化为确定性代码。
- 只支持 `.xlsx`、`.xls`、`.csv`，不扩展 PDF、图片、Word 或网页。
- 不修改匹配算法、候选评分、重要性水平和现有报告业务口径。
- 不新增运行时依赖，不修改原始输入文件。
- 所有现有文件修改前备份到 `C:\Users\27651\BackUp\bank-reconciliation-tool_<时间戳>\` 并校验。
- 所有新行为必须先看到预期失败测试，再写最小实现。
- 中文文档和注释使用 UTF-8，写入后检查问号、乱码和 Unicode 替换字符。
- 用户已明确同意在当前 `master` 分支实施并在完整验证后直接推送现有 GitHub 远端。

```python
@property
def has_blockers(self) -> bool:
    return any(item.status == "阻止" for item in self.items)

@property
def has_warnings(self) -> bool:
    return any(item.status == "提示" for item in self.items)

def blocker_message(self) -> str:
    return "\n".join(
        f"• {item.name}：{item.explanation}"
        for item in self.items
        if item.status == "阻止"
    )

def warning_message(self) -> str:
    return "\n".join(
        f"• {item.name}：{item.explanation}"
        for item in self.items
        if item.status == "提示"
    )

def to_dataframe(self) -> pd.DataFrame:
    return pd.DataFrame(
        [item.as_dict() for item in self.items],
        columns=(
            "检查项目", "银行流水结果", "银行日记账结果",
            "双方比较结果", "状态", "说明",
        ),
    )
```
