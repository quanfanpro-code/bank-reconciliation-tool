# 采用自动化优先的重要性分流

银行流水核对中的候选歧义、字段冲突、范围限制和重大事项不再被统一设计成“必须人工复核”。程序只要仍具备计算条件就运行到底：能够建立确定关系的形成自动确认，多个合理答案但交易组完全闭合的形成整组勾稽，其他可量化影响按明显微小错报临界值、实际执行重要性水平和累计差异池自动分级；超过门槛或无法量化的事项输出高风险疑点和受限结论，但不阻止报告生成，也不要求人工填写后才算完成。

## 考虑过的方案

- 所有歧义和冲突强制人工：判断保守，但会把程序可以量化和归集的工作重新推给用户。
- 低于阈值直接虚构最可能配对：自动化率高，但会把金额风险判断错误地当成交易身份依据。
- 自动确认、整组勾稽和重要性分流三层结果：既保持自动化，也不制造不存在的逐笔关系，因此采用。

## 后续影响

- “待人工复核”不再是运行必经状态，改为不阻断流程的“疑点事项”。
- 重要性水平决定风险等级、展示顺序和说明，不决定程序是否继续运行。
- 只有文件无法读取、日期金额无法形成任何有效交易等技术上不可计算的情况才允许中止。
- 报告必须区分逐笔自动确认、整组勾稽、自动归集和范围受限结果。
