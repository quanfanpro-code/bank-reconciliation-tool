# 先验证列身份，再核对流水

用户确认将修改桌面程序和 Skill，完成后更新 README、提交并推送。银行流水和银行日记账仍是两份核对输入，批量按户处理，沿用现有五表报告。

- 先读入整张表，识别日期、交易金额或收支分列、方向、本户账号、币种和余额。判断使用列的业务含义与数据，字段所在列号不影响结果。
- 分开识别交易金额与手续费、交易日与起息日、交易后余额与可用余额、本方与交易对手、原币与本位币。工具生成的模板字段也必须识别。
- 不同本户账号应当拦截。两列都是合理候选且数据也不能区分时，列出冲突字段和候选列，仅暂停该户。桌面版提供手工选列。Skill 通过提问让用户选择，其他账户继续。程序和 Skill 共用判定逻辑。
- 用原表日期、每列内容及逐笔余额变化验证选列。不得拿对账吻合率来反推字段，也不以某个银行名称硬编码例外。由用户确认的列也要检查所选字段角色与金额口径。

验收覆盖「账户」跨户、付款方账号、对方币种、手续费、起息日、可用余额、收付分列、原币和本位币、候选列平局和换序。复跑现有九户，对比读入笔数、收支、日度和月度汇总，核查笔数金额没有变化，冲突户不会输出正式报告。
