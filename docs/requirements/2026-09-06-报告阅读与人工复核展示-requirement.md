# 报告阅读与人工复核展示需求

用户已在本轮确认“需求说清楚了，继续推进”，并明确本轮只改输出；后端算法如确需改变，必须另行说明理由并取得批准。本需求覆盖此前被否决的报告排版，不重做银行流水核对算法。

## 使用场景与已确认内容

注册会计师只提供单账户银行流水与对应银行存款序时账。先看月度收支发生额与余额，再看逐笔或整组关系，对人工全查和人工抽样的事项就地选择结果并保存。

- 月度发生额及余额在同一张表；年月不混用、收支分别比较、年度发生额可合计，余额不相加，缺失明确显示。
- 一对一单独“逐笔核对”，双方并排。一对多、多对一、多对多单独“整组核对”，汇总在前、完整组成在下，默认可折叠。
- 整组双方笔数、收入、支出、差额、依据、当前结果清楚可读。银行与序时账组成分块，不能暗示逐笔配对；汇总文字与原始金额列分开，不重复加总。
- “人工全查”“人工抽样”保留现有入选规则，组成默认展开。每项只在主行选择一次结果；已有替代对应的组成就地展示，不要求另找表、导入或补资料。
- 未对应原始记录有独立可读入口。原始对应分类保留，人工否定或替代后明确显示每条记录当前去向。
- 核对结论、月度核对、逐笔核对、整组核对、人工全查、人工抽样是固定阅读入口；“未对应记录”承接单边。其他专题、每日分析、输入详情、候选和计算表默认隐藏，仍可取消隐藏查看。

## 范围与禁止变更

本轮只允许报告展示、筛选导出对展示表的适配、测试和说明文档。matcher、matching_policy、balance、复核事项、输入预检查与数据读取、重要性和抽样参数、现有人工选择生效算法均不得改变。无需新增依赖、宏、资料入口、账务调整、责任人或处理日期。不重建EXE；沿用源码启动入口。

## 需求追问复核

目的、用户、资料、范围、成功条件、月度合表、一对一拆表、整组结构、人工两类入口、唯一选择、单边留存均已有用户回答。资料不足时仍保留原程序结论，不发明业务原因。原始分组与当前有效关系区分，筛选以整项隐藏保持组成完整；这些是已确认方案的实施细节，不要求用户重复回答。

## 验收标准

1. 真实报告主表不因专题有数据而增加；有效原始记录完整覆盖。
2. 一对一同一行并排；2对3样例有1个组汇总、2条银行组成、3条序时账组成，不能交叉配对。
3. 收付混合组显示两侧收入和支出，原始金额求和不会包含组汇总或替代候选。
4. 每个全查/抽样事项只有1个下拉；默认展开组成，选择后实时展示现有计算结果。
5. 月度收支和余额同屏，缺余额不补0；原取数结果和计算规则不变。
6. 真实Excel检查默认/展开视图、选择、否定、替代、冲突、保存重开、整组筛选；源文件不变。
7. 比较本轮前后原计算表与后端文件；完整测试通过、README和复核报告更新、提交推送现有工作分支。
