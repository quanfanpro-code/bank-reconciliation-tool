# 银行对账技能全面修复需求

## 背景

对提交 `e5ae8d468096a35f148f5caa982d748deb43f078` 的独立复核记录了 22 项问题。问题包括读漏工作表、读错收支方向、把不同订单当成一笔退款、把已经能核清的交易改派人工，以及把月中余额写成月末余额。原有 53 项相关测试通过，这些问题由补充样例复现。

## 已确认的业务要求

- 每个账户以一份银行流水和一份公司银行日记账为业务输入。仍可单户核对或从两个目录批量核对。
- 支持不同银行和不同记账软件的版式。换表头、列顺序、金额写法或工作表名称时，同一批业务应得到相同结果。账号、币种、收支方向、原交易编号或容差真的变化时，核对结论随事实变化。
- 由驱动技能的当前 Agent 在读表阶段解释原表的业务字段。它结合两份文件的工作表、上下文表头、实际行值和余额核实含义，并把列映射交给程序验证。程序识别出的常用列可作为建议，未命中固定表头也要进入这一步。至少用两套词表未收录的表头验证实际技能能自行识别并得到同一核对结果。
- 程序和 Agent 负责读两份原表、验证字段、补查组合和完成核对。程序先验证收支方向、逐笔及合计金额、日期容差、账号和币种。Agent 对照各笔实际日期、摘要和附言里写的用途或所属月份，以及对方和业务编号，判断哪组对应。程序再检查同一原行是否被多组占用，选出整户的一套结果。所有可用证据和核对效果都相同时，用固定顺序落定。现有表写选定的原行、采用依据和剩余差额。两项重要性金额用于说明差异大小和排序。
- 核对工作由技能做完。用户给出输入位置后，沿用本次显式设置和项目默认设置。陌生表头、重复导出、字段歧义、Agent 超时、候选较多、断档和剩余差额都由技能在账户内继续处理。日表、月表和交易明细保留已确定的结果，某个原值两表都确实没有时，只对该项写清查到的原行、可计算金额及范围。原始行按实际状态完整交代。
- 只有程序和 Agent 已用尽现有两表的可行办法、剩余异常确实重大，并且后续确实依赖用户的业务判断或权限时，才提出该项必要决定。例如技能算清一笔少记款的日期和金额，公司正式更正账目由有权限的人批准。程序的搜索上限、同分候选、超时、单纯超过重要性金额，以及报表中的差额说明本身，均不能触发人工处理。
- 继续输出核对总览、月度核对、日度核对、待核对、待核对明细和交易明细。保留原日期、收支、账号角色、来源文件、工作表和原行号。现有“待核对”页承接需要说明的异常。
- 修复全部 22 项，沿用已有读表、计算、匹配和出表能力。同步更新仓库 README、技能 README 和实际执行说明。验证通过后提交并推送至已核实的 GitHub 上游分支。

## 逐项验收口径

编号对应本次独立复核记录。

| 编号 | 验收要求 |
| --- | --- |
| 1 | 同一 Excel 内同户的交易续页均计入。封面、汇总和重复导出的页有依据地排除，行号能回到各自工作表。 |
| 2 | 批量能通过表内本方身份配户。文件名与表内账号不一致时，报告显示已核实的表内身份。保留账号前导零。 |
| 3 | 公司账号用于配户，对方账号用于逐笔验证。对方账号原文可证实不一致时，该对交易不能仅靠同日同额确认。 |
| 4 | 同义表头和列顺序改变时保留相同的订单、银行流水和业务编号语义。不同类别的编号各按其业务含义比较。 |
| 5 | 一个账户未能成对时，先查表内身份、账户及重复导出，列出该户实际读到的一侧及有效范围。其余账户照常出表，批量结果说明每户已完成的工作。 |
| 6 | 带符号金额、正数加方向、带负号且重复标注方向的等价输入得到相同收支。保留真正负数冲回的含义。 |
| 7 | 一行同时列收入和支出时保留两个方向，日表、月表与原表分别复算一致。 |
| 8 | 金额单元格中的明确币种在取出数字后仍用于核对。不同货币的相同数字不能直接配对。 |
| 9 | 金额解析失败时，先复读原单元格及同列格式并正确处理符号、币种和公式值，再用两表内可核实的同笔编号、前后余额和收支原值复算。确实未列明的金额单独标出原行及影响，其他可计入金额照算。 |
| 10 | CSV 空行不改变后续原行号或自行继承交易日期。Excel 日期依据工作簿的日期系统换算。 |
| 11 | 不同订单的付款和退回款各自核对。能够关联同一原付款的退回款仍按原业务处理。 |
| 12 | 第六笔及后续竞争记录纳入原文验证。确认唯一对应后自动完成已经核清的一笔。 |
| 13 | 月度总额仍独立计算。确认跨日的一对一及多笔关系时，使用本次配置的日期容差。 |
| 14 | 搜索达到上限时补查可行组合，再由程序比较并选择一套结果。加入无法入组的交易或改变原表排序，不应改变同一批可区分交易的选配结果。两种组合覆盖相同原行时可确认整组。 |
| 15 | 同一对原行上已经核实的业务冲突在各轮候选中一致生效。Agent 请求超时或答复无效时，由技能按相互竞争的原行重新发起一次有针对性的核对，并继续使用已核实的证据。程序负责最终选配和出表。 |
| 16 | 两表合计相同仍保留强重复线索。只有原表能证明为重复导入时才从汇总中排除副本，并保留原行出处。 |
| 17 | 月中结束的查询按截止日显示余额，月末余额栏反映有证据支持的月末值。 |
| 18 | 仅有一侧提供余额时，该侧的已知余额保留在现有日表、月表。 |
| 19 | 已查明的余额断差写入日表。同户同一时点的两个余额矛盾时，保留各自的数与差额。 |
| 20 | 已知明细缺口限制余额支持的确认。共同订单等独立业务证据仍可用于确认。 |
| 21 | 银行原表明确列明查询范围、零发生及余额时，零交易也能正常出表。 |
| 22 | 移除按重要性金额直接派发人工全查和抽查的技能流程。技能查完两表内的依据，按差额及影响写入原有工作表。其他月份新增大额记录不改变本笔的处理。 |

再用模型开发时未依赖的列名和工作表顺序验证。固定业务事实改格式时结论相同，固定格式改业务事实时结论随之改变。

从真实技能入口验证，输入和设置送到程序后，22 个复核场景均可由技能得出结果，包含确定配对、算出差额、验证零交易或写明某户已核对的实际范围。检查返回信息和现有 Excel，以上场景不得产生要求用户选列、挑配对、补交材料、再次运行、人工抽查或人工全查的任务。
