# 银行流水核对及报告改版

需求已在 2026 年 11 月 23 日确认，用户授权实施、更新 README、提交和推送。

- 桌面版每户只读取银行流水和银行日记账。独立校验金额列、收支方向和读入记录，一列金额加方向与两列收支金额分别处理。
- 先确认有充分证据的逐笔对应，已确认的原始行不参加后续拼组。再处理剩余的跨日和多笔对应。前后余额相同、剩余收支组成唯一且无业务冲突时，允许直接对上合并记录。保留退款和重付的各笔原始记录。
- 逐日逐月均按两份原表各自的日期计算，不移动原始收支。月度、日度金额和余额使用原数据，跨日已对上的交易与仍未对应的交易分别说明。
- 只让实际待解决的问题进入人工分流。明显微小错报临界值和实际执行重要性水平均从本次配置读取。小额未解释差额留在明细，中间金额按现有规则抽查，超过实际执行重要性水平的逐项核对。通用表头提示不反复生成逐笔待办。
- 正式报告只含核对总览、月度核对、日度核对、待核对、交易明细。保留双方交易日期、用途、对方、凭证、原始出处和可编辑的核查结论与备注。待核对可跳到交易明细。去掉已对平比例、程序评分、临时候选和重复工作表。

验收覆盖分列读取、同日记账顺序不同、同日直接对应不会被弱组合抢占、跨日、两笔合记一笔、七笔合记一笔、退回和重付、存在真实差异时仍按用户阈值处理，以及工作簿五表、金额、原行和跳转。用原始银行流水和日记账复算日度、月度收支和交易归属，保留既有原始文件和历史报告。

桌面版完成后另行实现单户和双目录批量核对 Skill。复用验收后的同一引擎，语义复核由运行 Skill 的 Agent 完成，报告维持相同口径。个人模型配置不进入仓库或 Skill。
