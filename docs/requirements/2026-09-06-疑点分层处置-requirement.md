# 疑点分层处置需求（明显微小自动确认 + 中风险等距抽样）

日期：2026-09-06
来源：用户在真实数据（东方农博）核对结果上的两条连续指令。

## 背景

真实数据跑出的疑点事项 2,291 行，其中：

- 低风险 1,555 笔，绝大多数是"零差额、金额 ≤ 明显微小错报临界值（默认 5,000 元），仅因业务依据不足或候选歧义被拦下"的匹配；
- 中风险 672 笔，全部留给人工，数量仍然过大。

用户原话：

1. "低风险的就不用看了，程序能对上就对上，不要给人工了。"
2. "中风险的，按时间排序等距抽样，样本数量最多和高风险的一致。"

## 需求

### R1 明显微小零差额匹配自动确认

同时满足以下全部条件的候选，直接置为"自动确认"，不再列为疑点：

1. 差额为零（`total_diff_li == 0`）；
2. 组金额 ≤ 明显微小错报临界值（`clearly_trivial_threshold`，默认 5,000 元）；
3. 疑点原因仅属于以下三类弱证据原因（可单可组合）：
   - 综合可信度低于自动确认门槛；
   - 金额和日期相同但业务依据不足；
   - 候选歧义；
4. 不在余额断档窗口内（无 `overall_scope_limited` 标记）。

判断依据中写明"金额明显微小自动确认"及被放宽的原始疑点原因，保持可追溯。

### R2 不放宽的边界

以下情形即使金额明显微小也维持疑点，不在 R1 放宽范围：

- 关键文字字段冲突（如工资所属期间不一致、批量与单列混合）；
- 跨月多对多；
- 仅日月总额闭合缺少业务组边界、批次边界不足；
- 已保留完整组成但缺少跨双方范围闭合证据；
- 断档窗口内（范围未知）。

理由：这些不是"对上"，而是存在未决冲突或范围不明。

### R3 中风险等距抽样

- 对象：风险等级为中风险、且会进入疑点事项输出的候选（疑点事项与自动归集事项两类状态）。
- 方法：按候选内最早交易日期升序排序，等距（系统化）抽样。
- 样本量：k = min（中风险候选数，高风险候选数）。高风险为 0 时抽 0 笔（用户按字面确认）。
- 抽中：维持疑点，建议动作为优先核查。
- 未抽中：仍列示在疑点事项表中（不删除、不改风险等级），但建议动作标注"等距抽样未抽中，随同低风险留存备查，本次不留人工"，判断依据追加抽样标记。
- 高风险、范围未知维持全量人工核查，不受抽样影响。

### R4 报告透明性

- 总览结论区增加两行统计：中风险抽样总数、抽中待核查数。
- "截止性差异"表来源于业务链事件的跨期标记，与候选状态无关，R1 自动确认不得影响该表列示（含容差窗口内跨期的小额配对）。

### R5 历史规则的取代

2026-08-09 设计规定"候选歧义必须挡住金额完全一致和明显微小两条自动确认路径"。本轮经用户明确指令，在"零差额 + 金额 ≤ 明显微小临界值"范围内取代该规则；超过明显微小临界值的候选歧义仍维持疑点。需求文档与设计文档如实记录本次取代关系。

## 验收标准

1. 满足 R1 条件的候选状态为"自动确认"，风险等级为正常，判断依据含"金额明显微小自动确认"。
2. R2 所列情形维持疑点不变。
3. 中风险抽样数量恰为 min（中风险数，高风险数），抽中名单按日期等距分布；未抽中者建议动作为留存备查。
4. 总览新增中风险抽样统计行。
5. 截止性差异表行数不因 R1 减少。
6. 真实数据（东方农博）重跑：低风险疑点大幅转为自动确认；中风险疑点中仅抽中部分标注需人工；疑点事项表仍完整列示未抽中项。
7. 全量测试通过；被取代的旧断言按新口径更新并在审查报告中说明。
