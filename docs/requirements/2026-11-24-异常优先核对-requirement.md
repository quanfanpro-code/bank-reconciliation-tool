# 银行流水核对先完成匹配再列异常

用户已确认方案并授权实施、更新 README、提交和推送。使用同一账户的银行流水与日记账两份文件，交付修好的问答 Skill。共用代码仅为 Skill 接入、复用剪枝或正确出表作必要调整。

日期容差从逐笔核对开始生效。容差内同向同额且唯一、原表没有明确冲突时自动确认。复用双向递归剪枝查合笔。几种配法覆盖同一批记录、收支分别一致时，整组确认并保留原始日期和行号。窗口内存在明确矛盾或不同配法会留下不同的未匹配记录时，列出具体冲突。

用途由当前 Agent 阅读双方原文判断。系统核验各自的金额、方向、日期、原行和引用。空白或泛称没有造成明确矛盾时继续核对。

输入缺少某月逐笔明细时，在该月说明并保留账面及完整月份的核对结果。空摘要、缺流水号、模型未回答、正好超过实际执行重要性水平均不构成异常。两个重要性设置用于剩余差异的处置，保留日度、月度、总览、待核对、交易明细。

验收使用用户提供的真实输入，复核用户指出的同额记录、缺月和误报，按原表复算未对上金额和行号。检查候选冲突、方向相反和真实差额仍可见。
